## 1. 背景与目标

AutoCode 有两条改码路径，是同一个「改码前快照 + 可回退」问题在两个尺度上的实例：

| 路径 | 改码者 | 快照粒度 | 现状 |
|---|---|---|---|
| 任务流水线 | 阶段 runner（Develop/BugFix/Verify…） | **粗**：一个改码阶段一份 | FR-6 已有全量快照，本方案升级为增量 |
| 助手聊天（ad-hoc） | `SubmitAdhoc(a_bReadOnly=false)` 会话 | **细**：一轮提问一份 | **完全没有备份** |

目标：

1. **统一增量存储**：CAS（内容寻址仓库）——未变内容跨版本、跨来源只存一份只压一次；
2. **双粒度回退**：任务侧与助手侧各有「回退按钮 + 右侧▼下拉」入口，▼点击弹出**回退界面**（左：记录点列表；右：文件变动明细）；
3. **代码安全最高优先级**：回退可撤销、恢复原子、损坏可检测、崩溃残留可探测；
4. **零迁移兼容**：旧全量版本原样保留、照常可恢复；
5. 回退界面支持 **Tooltip、鼠标拖动列宽、列宽持久化**。

## 2. 统一模型

### 2.1 一个工程一个备份库

```
<工程根>/.autodev/
├── guide.md / record.md / tasks/…            # 现有，不动
└── backups/                                   # 新：工程级统一备份库
    ├── store/                                 #   内容寻址仓库（全局唯一内容一份）
    │   ├── <sha256-hex-64>.zst                #   zstd level 3（与现行 FR-6 同档）
    │   └── …
    ├── 0001.meta.json                         #   版本清单；序号全工程统一单调递增
    ├── 0002.meta.json
    ├── notice.json                            #   回退告知待注入标志（§6.3）
    └── _restore_tmp/                          #   仅回退执行期间存在（§4.4 崩溃探测依据）
```

- **版本 = 一份完整 manifest**（path → hash/size/mtime）。恢复任一版本 = manifest + store 取内容，**无版本间依赖、无链式合成**。
- 旧位置 `.autodev/tasks/<id>/backups/`（FR-6 全量版）**原样保留只读**，照常可列可恢复，不做迁移。

### 2.2 版本元数据 `NNNN.meta.json`（最终 schema，实施即此）

```json
{
  "seq": 17,
  "time": "2026-08-22T10:00:01",
  "kind": "turn",
  "owner": "task-20260822-093011",
  "stage": "Develop",
  "prompt": "帮我把登录超时改成可配置……",
  "summary": "……",
  "target": 12,
  "format": "cas",
  "files": {
    "src/main.cpp": { "h": "<sha256-hex-64>", "z": 12345, "m": 1724295201123 }
  }
}
```

| 字段 | 类型 | 必有 | 说明 |
|---|---|---|---|
| `seq` | int | ✓ | 全工程统一版本序号（0001 起，扫 `*.meta.json` max+1 分配） |
| `time` | string | ✓ | 备份时刻 ISO（`QDateTime::currentDateTime().toString(Qt::ISODate)`） |
| `kind` | string | ✓ | `stage` \| `turn` \| `rollback-pre` |
| `owner` | string | ✓ | 任务 id；助手档绑定任务时=该任务 id；工程全局助手档=`"global"` |
| `stage` | string | kind=stage | 阶段名（Develop/BugFix/…） |
| `prompt` | string | kind=turn | 该轮提问全文，**截断 2000 字**（列表列显 40 字，Tooltip 显全文存量） |
| `summary` | string | kind=stage | 阶段结束回填的改动摘要（≤300 字，沿用现行 `SetBackupSummary` 机制） |
| `target` | int | kind=rollback-pre | 即将回退到的目标 seq |
| `format` | string | ✓ | 恒 `"cas"`；旧全量 meta 无 `files` 字段即视为旧格式 |
| `files` | object | ✓ | 键=工程根相对路径（**正斜杠**），值：`h`=内容 sha256；`z`=字节数；`m`=mtime 毫秒 |

- `files` 三元组的用途：`h`——去重与恢复校验；`z`——界面大小列显示；`m`——回退预检「将被覆盖的改动」的廉价比对（§8 步骤 2）。
- 空/含 BOM 编码约定：meta 一律 **UTF-8 with BOM**（与现行 FR-6 meta.json 一致，读取时跳 BOM——沿用 `ListBackups` 现有写法）。
- 写盘协议：**先写全部 blob → 最后写 meta（临时文件 + `QFile::rename` 原子提交）**。meta 存在 = 版本提交完成。

### 2.3 kind 与产生时机

| kind | 时机 | 执行方式 | 触发点 |
|---|---|---|---|
| `stage` | 改码阶段启动 runner 前 | 后台 `std::thread`（沿用 FR-6 现路径） | `CTaskOrchestrator::RunCurrentStage` |
| `turn` | 助手**非只读**轮投递前 | **同步**（投递等快照完成） | `CTaskOrchestrator::SubmitAdhoc(a_bReadOnly=false)` |
| `rollback-pre` | 任一回退执行前 | 同步 | 回退引擎（§8 步骤 3） |

只读轮（`a_bReadOnly=true`，工具集仅 Read/Grep/Glob）不可能改码，**不产生版本**。排队自动续发轮与轮中介入（v1.0.60 `InjectUserTurn`）各自算一轮，投递前同口径快照。

### 2.4 所有权与删除

- 任务删除 → 删该 owner 全部版本 meta → GC（§4.6）；`owner="global"` 随工程存在；
- 回退恢复的是**整个工程源码树**（排除清单范围），不区分谁改的——版本列表是时间线，不是责任划分。

## 3. 方案选型（结论，已定案）

| 候选 | 结论 |
|---|---|
| 差分链 | 恢复需链式合成，坏一环波及后续全部 ✗ |
| ref 指针链（DSHAgentManage 所采） | 版本间耦合：中间不可单删、清理需重定基线（物化+改写 manifest+磁盘峰值）✗ |
| **CAS（本方案）** | manifest 只记 hash，版本互相独立；删除=并集 GC；恢复时 hash 复核可检测损坏 ✓ |

增量收益边界（诚实声明）：备份仍需**读**全部文件算 hash（与现状 FR-6 持平）；**压缩 CPU 与写入量**只发生在新增/修改内容上（主要收益）。stat 索引跳过读取列 P3 可选。

## 4. 存储层实施细则

### 4.1 可移植核心：`CBackupStore` 纯逻辑类（无 Q_OBJECT）

**存储引擎做成自包含类 `CBackupStore`，定义在现有 `CProjectManager.h/.cpp` 文件内**（类声明放 `CProjectManager.h` 的 SBackupVersion 之后、CProjectManager 类之前；实现放 .cpp 备份段）：

- **无 Q_OBJECT、无信号槽、不依赖任何 AutoCode 业务类**——依赖仅 Qt Core（QFile/QDir/QJson/QCryptographicHash）+ zstd + 传入的路径参数；
- 因此**零构建系统影响**（非 Q_OBJECT 类不需要 moc，不动 CMakeLists/vcxproj/.filters——规避本项目已知坑），同时**整类可原样拷贝到 DSHAgentManage 复用**（§15）；
- 「扫描+过滤」与「哈希+入库」解耦：过滤策略由调用方注入（`a_aScanRoots`/`a_pfFilter` 回调），AutoCode 传排除清单、DSH 传扩展名白名单——核心不关心；
- BOM 策略参数化（AutoCode 带 BOM、DSH 无 BOM）。

```cpp
// ===== [PortableCore] CBackupStore —— 以下整段为可移植核心，勿混入 AutoCode 业务依赖 =====
class CBackupStore {
public:
    // a_sBackupsRoot: 备份库根（AutoCode=<工程>/.autodev/backups；DSH=任务目录 backup\）
    // a_sSourceRoot : 被备份的源码根（工程根 / workDir）
    // a_bBom        : meta/notice JSON 是否写 UTF-8 BOM（AutoCode=true；DSH=false）
    CBackupStore(const QString& a_sBackupsRoot, const QString& a_sSourceRoot, bool a_bBom);

    // 备份范围谓词：返回 false 的文件不入库（由宿主项目注入过滤策略；同步遍历，无多线程）
    std::function<bool(const QString& a_sRelPath)> m_pfFilter;

    // —— 版本操作（§4.2/4.3/4.5 流程）——
    int  Backup(const QString& a_sKind, const QString& a_sOwner,
                const QString& a_sStage, const QString& a_sPrompt, int a_iTarget);   // →seq，0=失败
    bool Restore(int a_iSeq, QString& a_sErr);                                       // 原子恢复+hash 校验
    QList<SBackupVersion> List(const QString& a_sOwner) const;                       // 倒序；含 legacy 探测
    bool Diff(int a_iSeqOld, int a_iSeqNew, SDiffResult& a_stOut) const;             // manifest 三路对比
    int  PurgeOwner(const QString& a_sOwner);   // 删 owner 全部版本+GC，返回释放 blob 数
    int  GcOrphanBlobs();                       // 无引用 blob 清理
    bool HasRestoreTmp() const;                 // _restore_tmp 残留探测（崩溃恢复入口）

    // —— 回退告知标志（notice.json）——
    bool LoadPendingNotice(int& a_iTargetSeq, QString& a_sOwner) const;
    void SetPendingNotice(int a_iTargetSeq, const QString& a_sOwner);
    void ClearPendingNotice();

    // —— 回填（阶段摘要 / DSH 的行数统计等扩展字段，按 key 写入 meta 顶层）——
    bool SetMetaField(int a_iSeq, const QString& a_sKey, const QJsonValue& a_vValue);

private:
    QString m_sBackupsRoot; QString m_sSourceRoot; bool m_bBom;
    // HashFile / ScanNextSeq / BuildManifest / ReadMeta / WriteMetaAtomic 等私有工具
};
// ===== [/PortableCore] =====
```

### 4.2 BackupTree 流程（伪代码）

```
BackupTree(kind, owner, stage, prompt, target) → int
  1. 守卫：m_sProjectDir 非空且存在；owner 非空；kind 合法。否则 return 0
  2. sBackups = .autodev/backups；mkpath
     iSeq = 扫 *.meta.json 取 max+1（rename 失败=序号被并发占用 → 重扫重试，至多 3 次）
  3. 遍历工程根（排除清单 BackupExcludeDirs() 沿用，仅顶层一级生效，含 .autodev 自身 → 库永不递归自备）：
     每文件 f：
       a. 读全文 → h = sha256（QCryptographicHash::Sha256，hex 64）
       b. blob = store/<h>.zst；不存在 → ZstdCompressFile(f, blob)   // 复用现有匿名 ns 函数
          压缩失败 → 整版作废：本版尚无 meta，已写 blob 为无害孤儿（GC 兜底），return 0
       c. manifest.files[relpath(f)] = {h, z=QFileInfo(f).size(), m=QFileInfo(f).lastModified().toMSecsSinceEpoch()}
  4. 写 meta：临时文件 000N.meta.json.tmp → 写 BOM + QJsonDocument → rename 到 000N.meta.json
     rename 失败 → return 0
  5. return iSeq
```

要点：

- **并发提交协议**：内容先写、meta 原子 rename 后写。「任务后台备份线程 × 助手同步快照 × 用户回退」三者理论上可重叠（低概率，IsRunnerBusy 大多挡住）；不同 blob 并行写无冲突；seq 竞争由 rename 失败方重试解决。
- 老任务首次升级：第一次 BackupTree 全量入 store（等同基线），此后增量。
- 相对路径统一 `/`（`QDir::fromNativeSeparators`）。

### 4.3 RestoreTree 流程

```
RestoreTree(seq, err) → bool
  1. 读 <backups>/NNNN.meta.json（跳 BOM 解析）
  2. 分派：
     无 files 字段（legacy）→ 委托现有 RestoreSources(taskId…, seq, err) 旧路径
     （注意：legacy 版本号是任务内旧库序号，须按「旧库位置 + owner 任务」定位——
       ListUnifiedBackups 合并时给 legacy 版本打 bLegacy 并保留其原任务 id 于 sOwner，
       RestoreTree 对 legacy 转调旧接口即可）
     format=cas →
       ① 工程当前源码（排除清单内）移入 backups/_restore_tmp/（QDir::rename 每顶层项；
          与旧 RestoreSources 现有中转做法同思路）
       ② 逐 manifest 条目：store/<h>.zst → ZstdDecompressFile → 工程根对应路径
          （先 mkpath 父目录；目标存在先 remove）
          解压后**重算 sha256 与 manifest.h 比对**，不匹配 → err="store/<h>.zst 损坏
          （版本 #N 不可恢复，工程已还原）" → 走 ③ 回滚 → return false
       ③ 全部成功 → 删 _restore_tmp → return true
          任一步失败 → 清工程根半恢复内容（排除清单范围）+ _restore_tmp 拷回 → return false
  3. 恢复语义：排除清单范围内逐字节等于版本时刻；.git/build 等排除目录不动
```

### 4.4 崩溃残留探测（打开工程时，`CProjectManager::Open` 尾部追加）

- 扫 store：无任何 meta 引用的 blob → 静默 GC（`GcOrphanBlobs()`）；
- 发现 `_restore_tmp/` 存在 = 上次回退被进程死亡打断 → 交 UI 弹二选一（§8 前置分支）：
  「继续恢复」（重跑 ②，manifest 是确定目标，幂等）/「还原现场」（`_restore_tmp` 拷回工程根）。两路安全：当前态要么完整在 tmp，要么已完整拷出。

### 4.5 ListUnifiedBackups / DiffVersions

- `ListUnifiedBackups(owner)`：
  统一库扫 `*.meta.json` 过滤 `owner`；旧库 `BackupsDir(owner 任务)`（仅 owner 为任务 id 时）扫 `*.meta.json` 全收，标 `bLegacy=true`、`sKind="legacy"`；合并按 seq **倒序**（两库序号空间独立，排序键用 time 字符串 ISO 可比）；返回。
- `DiffVersions(seqOld, seqNew, out)`：两份 manifest 的 files 转 `QHash<QString, entries>` 后三路对比：
  仅在新=add；仅在旧=del；都有且 h 不同=mod。旧格式任一 → false（界面显示占位文案）。

### 4.6 GC

删除版本集合 S（PurgeOwner / 未来 MaxVersions / 手动）→ 重扫剩余全部 meta 的 files `h` 并集 → 删 store 中无引用 blob。版本量百级、千文件量级，毫秒级。

- 两表通用样式：`selectionBehavior=SelectRows`、`setEditTriggers(NoEditTriggers)`、`SelectionMode=SingleSelection`、`verticalHeader()->setVisible(false)`、`setAlternatingRowColors(true)`、`setSortingEnabled(false)`（时间线固定倒序，禁排序防语义混乱）。

### 5.3 左表：记录点列表

**列定义（7 列，顺序固定）**：

| # | 列 | 数据来源 / 派生规则 | 默认宽 | resize 模式 |
|---|---|---|---|---|
| 0 | `#` | `iSeq` | 40 | Interactive |
| 1 | `时间` | `sTime` → `yyyy-MM-dd HH:mm:ss`（当年可省年份显示 `MM-dd HH:mm`） | 118 | Interactive |
| 2 | `类型` | kind 派生（见下） | 72 | Interactive |
| 3 | `名称摘要（一句话）` | DisplayTitle（见下），**stretch 列** | 260 起步 | Interactive + `setStretchLastSection(true)` 不用——用显式 stretch（见 §5.6 说明） |
| 4 | `改` | 相对上一记录点的 mod 数 | 40 | Interactive |
| 5 | `删` | 相对上一记录点的 del 数 | 40 | Interactive |
| 6 | `增` | 相对上一记录点的 add 数 | 40 | Interactive |

**类型列派生（`KindLabel(meta)`）**：

| kind | 显示 |
|---|---|
| `stage` | 阶段名（`sStage`，如 Develop/BugFix） |
| `turn` | `助手轮` |
| `rollback-pre` | `回退前快照` |
| `legacy` | `旧全量` |

**名称摘要派生（`DisplayTitle(meta)`，一句话总结）**：

| kind | 规则 |
|---|---|
| `stage` | `sSummary` 非空 → 取其（≤40 字加 `…`）；空 → `<阶段名>前快照`（阶段未结束时打开的暂态） |
| `turn` | `sPrompt` 取首 40 字 + `…` |
| `rollback-pre` | `回退到 #<target> 前的现场` |
| `legacy` | `sSummary` 非空 → 同上；空 → `旧版全量快照` |

**统计列（改/删/增）计算**：

- 打开对话框时一次性构建：`ListUnifiedBackups(owner)` 得倒序列表后，对**每个 CAS 版本**与「列表中它的上一条」（seq 更小的相邻条）做 `DiffVersions(prev, cur)` 取三计数缓存到行数据（`QMap<int, SDiffResult>`）；
- **最老一条（无上一条）**：改/删 显示 `—`；增 显示该 manifest 文件总数（基线概念：这份快照包含了多少文件）；
- **legacy 版本**：三列均 `—`（旧全量无 manifest，不做「现场哈希一遍」的成本换算）；
- 上一条是 legacy 而本条是 CAS：也 `—`（对比无意义）。

**Tooltip（全文防截断）**：

| 列 | Tooltip 内容 |
|---|---|
| `#`/`时间` | 完整 ISO 时间 + kind 全称（如 `2026-08-22T10:00:01 · 助手轮次快照`） |
| `类型` | kind 说明（`阶段前快照：该阶段启动前捕获` / `助手轮前快照：本轮提问投递前捕获` / `回退执行前的现场保护快照` / `旧版全量快照（FR-6）`） |
| `名称摘要` | **全文**：stage=summary 全文；turn=prompt 存量全文（≤2000 字）；其余同列显 |
| `改/删/增` | `修改 N · 删除 M · 新增 K（相对上一记录点 #<prev>）`；`—` 时 `旧格式/基线，无对比数据` |

实现：每个 cell 用 `QTableWidgetItem::setToolTip()`（或 `setData(Qt::ToolTipRole, …)`）。

**行序**：倒序，最新在最上（与现 CRollbackDialog 一致）。首行（最新）默认选中并联动右表。

### 5.4 右表：文件变动明细

选中左表某行 → 右表显示该记录点相对上一记录点的文件变化：

**列（3 列）**：

| # | 列 | 内容 | 默认宽 |
|---|---|---|---|
| 0 | `文件路径` | 相对路径（`/` 分隔），stretch | 420 起步 |
| 1 | `变化` | `修改` / `新增` / `删除` | 56 |
| 2 | `大小` | `12.3 KB → 15.1 KB`（修改）；`— → 4.5 KB`（新增）；`8.2 KB → —`（删除）；用 `FormatSize()`（B/KB/MB 两级小数） | 120 |

- 排序固定：按 变化类型（修改→新增→删除）再按路径字典序；
- Tooltip：路径列=完整路径；大小列=`旧 <hash 前 8> → 新 <hash 前 8>`（技术排查用）；
- **占位态**：选中 legacy / 基线（最老一条）→ 右表清空 + caption 显示
  `旧全量快照：无增量明细（可直接回退）` / `基线记录点：无上一记录点可对比`；
- caption（`m_pLblFilesCaption`）：`#17 相对 #12 的变化 —— 改 3 · 删 1 · 增 2（含两记录点之间的一切磁盘改动）`。

### 5.5 交互与回退动作

- **选择联动**：左表 `itemSelectionChanged` → 右表刷新（含占位态）；`m_pBtnRestore` enable=有选中；
- **双击行** = 点「回退到此记录点」（`cellDoubleClicked`）；Enter 键同效（左表 keyPressEvent 补回车）；
- **回退动作**（对话框内不直接动文件，emit 结果交主窗口——与现 CRollbackDialog 职责边界一致）：
  `accept()` 关闭并 `SelectedSeq()` 返回选中 seq；由 `CMainWindow::OnRollbackTo`（§8）执行守卫/预检/快照/恢复；
- **打开时机守卫**：任务 Running 时任务侧按钮已禁用；若打开后任务恰好起跑，回退动作处 `IsRunnerBusy` 兜底拒绝（§8 步骤 1）；
- 空态：无任何版本 → 两表空 + 说明行「暂无记录点（改码阶段/非只读助手轮会自动产生）」+ `m_pBtnRestore` 禁用。

### 5.6 持久化（列宽 / 分割条 / 窗口几何）

全部走 **exe 目录 config.ini `[Layout]` 节，Base64 存储**，与现行 `[Layout] VSplit`（任务列表分隔条）完全同机制（写法参照 `CTaskListPanel` 的 VSplit 存取实现）：

| 键 | 内容 | API |
|---|---|---|
| `RollbackVerHdr` | 左表列头状态（列宽/顺序/可视性） | `m_pTableVersions->horizontalHeader()->saveState()` / `restoreState()` |
| `RollbackFileHdr` | 右表列头状态 | 同上 |
| `RollbackSplit` | QSplitter 位置 | `saveState()/restoreState()` |
| `RollbackGeo` | 对话框几何（尺寸+位置） | `saveGeometry()/restoreGeometry()` |

- 保存时机：`hideEvent`/析构 时统一写一次（拖动过程不写盘）；
- restore 失败/无键 → 用 §5.3/5.4 默认宽；摘要列 stretch 的实现：默认宽给足 + `horizontalHeader()->setStretchLastSection(false)`，所有列 `Interactive`（用户要求「允许鼠标拖动列头宽度」，全列可拖；首次打开用默认值）；
- 头部设置：`setSectionsMovable(false)`（防拖乱列序）、`setSectionResizeMode(QHeaderView::Interactive)`、`setMinimumSectionSize(24)`。

### 5.7 对话框数据流（打开时一次性构建）

```
ctor(owner)：
  1. m_aVersions = m_pPm->ListUnifiedBackups(owner)          // 倒序
  2. 逐条（i 从 0=最新）：
       CAS 且 i+1 < size 且 Versions[i+1] 也是 CAS：
         DiffVersions(Versions[i+1].iSeq, Versions[i].iSeq, st) → 缓存 m_aDiffBySeq[iSeq]
       （最老/legacy → 无 diff，界面按 §5.3 占位规则显示）
  3. 填左表（含 tooltip/统计列/选中首行）→ 联动右表
  4. m_pLblSummary 文案组装
```

性能口径：百版本 × 千文件 QHash 对比，一次性构建毫秒~几十毫秒级；不在每次选择变化时重算（diff 已缓存）。

## 6. 助手侧实施细则

### 6.1 轮前快照挂点（`orch/CTaskOrchestrator.cpp`）

```
SubmitAdhoc(a_sText, a_bReadOnly, a_sTaskId)
  ├─ a_bReadOnly == true → 原路径直投（无版本）
  └─ a_bReadOnly == false
       ① iSeq = m_pPm->BackupTree("turn", 当前档 owner, "", a_sText 截 2000, 0)
       ② iSeq==0 → 不阻断投递；发 sigAdhocEvent("backup_failed",
          "本轮无回退快照（备份失败，详见状态提示）")   // 用户必须知情
       ③ 原路径投递（排队续发/轮中介入的续发点同样在投递前走 ①）
```

- **owner 取值**：当前助手档绑定任务的=该任务 id；工程全局档="global"（与 `SwitchAssistantArchive` 的档位一致；实施时从档位状态取，勿重复发明）；
- **同步性论证**：CAS 读全树算 hash，8MB 源码亚秒、200MB 树 1~2 秒，交互可接受；投递必须等快照完成（杜绝与 Agent 写文件竞态）。预留配置 `[Backup] TurnSnapshot`（`sync` 默认 / `async` 仅改 UI 反馈形态不改语义），P1 可不做。

### 6.2 会话撤销 vs 代码回退（边界，写入帮助文档）

| | `↶ 回退`（现有，不动） | 回退界面（新增） |
|---|---|---|
| 作用层 | **对话层**：撤销最后一条提问（sid 栈回退） | **文件层**：工程源码恢复到某记录点 |
| 互相影响 | 不动磁盘 | 不动 sid 栈 |

两操作正交不联动；代码回退后助手上下文对齐靠 §6.3 告知注入，而非删对话。

### 6.3 回退告知注入（双侧）

- `notice.json`（`.autodev/backups/` 下）：`{ "pending": true, "target": 12, "time": "...", "owner": "..." }`（UTF-8 with BOM，同 meta 约定）；
- 回退成功 → `SetPendingNotice(targetSeq, owner)`；
- **助手侧**：下一次 `SubmitAdhoc` 投递前检测 `LoadPendingNotice`，有则 prompt 前置：

  ```
  【系统回退通知】工作目录已回退到版本 #N（<时间>）：此前对话中描述的文件修改已不
  存在于磁盘。请以当前磁盘内容为准，不要基于已被回退的修改继续工作。
  ```

  注入后 `ClearPendingNotice()`（一次性）；
- **任务侧**：任务回退置 Stopped；若后续走 `--resume` 续跑（停滞恢复/断点路径），同样前置注入；全新进程阶段（prompt 由磁盘产物重建）不需要。

## 8. 回退引擎（`CMainWindow`，两入口共用）

```
OnRollbackTo(a_pTask, a_iSeq)          // 任务侧入口（对话框 accept 后）
OnRollbackTurnTo(a_iSeq)               // 助手侧入口
  0. 崩溃残留前置：若存在 _restore_tmp → 弹「继续恢复 / 还原现场」二选一，处理完才继续
  1. 守卫：任务非 Running && IsRunnerBusy()==false（挡助手与任务双侧）
  2. 预检确认框（破坏性预检）：
     - 恢复 X 个文件、删除 Y 个（当前有而目标 manifest 没有）——DiffVersions(目标, 当前即时扫描) 或
       目标 manifest vs 最新记录点 manifest（取后者，零额外扫描）
     - 警示清单：当前树中 (z,m) ≠ 目标 manifest 对应条目的文件里，且 ≠ 最新记录点条目的
       （= 最新记录点之后又有人工/别来源改动，回退将覆盖）——逐个列出（≤20 条 + 「等 N 项」）
     - 文案：「当前代码会先自动快照为新的记录点，随时可再回退撤销」
  3. BackupTree("rollback-pre", owner, "", "", target=a_iSeq)
     失败 → 中止 + Critical 告警（宁可不回退，不可丢现场）
  4. RestoreTree(a_iSeq, sErr)
     失败 → Critical（工程树已由 §4.3 还原）+ return
  5. 收尾：
     任务侧 → 任务置 Stopped + SaveTask + 刷新两表 + 状态栏
       「[任务名] 已回退到 #N（当前现场已存为 #M）」
     助手侧 → 对话流插事件徽章「已回退到 #N 之前（现场已存为 #M）」（复用 sigAdhocEvent）
     双侧 → SetPendingNotice(N, owner)（§6.3）
```

## 9. 代码安全的六道防线

| # | 防线 | 机制 |
|---|---|---|
| 1 | 回退可撤销 | 回退前自动快照 rollback-pre（§8 步骤 3） |
| 2 | 恢复原子性 | `_restore_tmp` 三步中转，任一步失败整体回滚（§4.3） |
| 3 | 损坏可检测 | 恢复时逐文件 sha256 复核，坏 blob 拒绝恢复（§4.3） |
| 4 | 运行互斥 | 任务 Running / 助手忙禁用入口 + 引擎 IsRunnerBusy 兜底（§8 步骤 1） |
| 5 | 崩溃可恢复 | 启动探测 `_restore_tmp` → 继续恢复/还原现场（§4.4、§8 步骤 0） |
| 6 | 半成品不暴露 | meta 原子 rename 提交；孤儿 blob 不入清单、GC 兜底（§4.2/4.6） |

## 12. 构建与收尾流程（项目规则摘录，实施会话必读）

1. **只编 Release|x64**（用户不用 Debug）；构建走 cmake；新增 Q_OBJECT 类必须同步 CMakeLists+vcxproj+.filters——**本方案零新增源文件，特意规避**；
2. 文件编码：源码 UTF-8 with BOM；改 `.bat` 保持 ANSI(GBK)+CRLF；
3. UI 文字 11pt 缺省（复用 `setPt11`）；命名守匈牙利（局部 `i/s/a` 前缀、成员 `m_`、参数 `a_`）+ K&R 大括号；
4. 交付自检：空指针/泄露/悬垂/双重释放/越界/未初始化/资源泄露/溢出除零 逐条过新代码；
5. **收尾顺序恒为：先编译 → 读 `build/gen/AutoCodeVersion.h` 的 AUTOCODE_VER_MAJOR/MINOR/BUILD → readme.txt 追加 `[YYYY-MM-DD] [vX.Y.N] 摘要 - 文件`**；
6. 部署副本（`Execute - 打包\AutoCode1.exe` 等）不自动生效，需提醒用户替换重启；
7. 启停 AutoCode 由用户管理，勿自行关闭。

## 13. 决策记录（已定案 / 待确认）

**已定案**：

1. 存储路线 = CAS（否决差分链/ref 链，理由 §3）；
2. `CRollbackDialog` 同名原地重写（避免新增 Q_OBJECT 文件的构建同步坑）；
3. 原「回退」按钮与新增▼下拉**打开同一新界面**（一套版本视图，不维护两个对话框）；旧 QListWidget 版界面退役；
4. 「↶ 回退」（对话撤销）与代码回退正交不联动（§6.2）；
5. 旧全量版本：可列可回退，统计列/明细显示 `—`+占位说明，不做现场哈希换算；
6. meta/notice JSON 一律 UTF-8 with BOM（随 AutoCode 现行 FR-6 约定；注意 DSH 项目是无 BOM，两项目不要互串）；
7. turn 快照同步执行（投递等待完成）；async 仅作未来 UI 形态预案；
8. 存储引擎 = 无 Q_OBJECT 纯逻辑类 `CBackupStore`，**内嵌现有文件**（`[PortableCore]` 标记段）——零构建系统影响，且整类可拷贝复用到 DSHAgentManage（§15）；过滤策略回调注入、BOM 策略参数化。

**待实施时向用户确认**：

1. 任务侧列表是否也想看到该任务助手轮的 turn 记录点（当前设计：owner 相同自然混排——助手档绑定任务时 turn 的 owner=任务 id，**会**出现在任务回退界面里；若希望任务界面只看 stage，加 kind 过滤即可，一行事）；
2. 回退界面是否需要「删除记录点」入口（P3 再说，默认不做）。

## 14. 风险与缓解

| 风险 | 概率 | 缓解 |
|---|---|---|
| blob 单点损坏波及多版本 | 低 | 防线 3 硬失败即时报错；P3 可加冗余 |
| 统一库并发（后台 stage 备份 × 助手 turn 快照 × 回退） | 低 | 提交协议（内容先行+meta 原子 rename）+ seq rename 竞争重试（§4.2） |
| 大工程 turn 前同步快照延迟 | 中 | §6.1 论证亚秒级常态；`[Backup] TurnSnapshot=async` 预案 |
| 用户混淆「↶ 对话撤销」与「代码回退」 | 中 | tooltip/界面文案明确「恢复工程源码到某记录点」；帮助文档补 §6.2 边界 |
| 左表统计列被误读为「该轮改动」 | 中 | caption/tooltip 明示「相对上一记录点，含两记录点之间的一切磁盘改动（含人工修改）」 |
| manifest 体积（万级文件 × 64hex） | 低 | 千文件≈几百 KB JSON，可直接 QJsonDocument；万级再考虑逐行流式 |

## 15. DSHAgentManage 适配指南（本方案复用改造）

> 用户已明确：本方案将同时用于改造 DSHAgentManage（其原设计《增量备份回退方案》为 ref 链路线，2026-08-21 v1.0）。本章给出平移路径：**可移植核心原样拷贝，挂点与过滤按 DSH 映射，ref 链特有机制整体裁撤**。

### 15.1 直接复用（零改动拷贝）

| 模块 | 复用物 |
|---|---|
| 存储引擎 | §4.1 `[PortableCore]` 整段：`CBackupStore` + `SBackupVersion`/`SDiffEntry`/`SDiffResult` + 类内 zstd 压缩/解压工具。拷入 DSH 任一现有 .h/.cpp（同样建议内嵌，规避 vcxproj 同步；DSH 若不忌讳新文件也可独立 `BackupStore.h/.cpp`，无 Q_OBJECT 即无 moc） |
| manifest schema | §2.2（DSH 构造传 `a_bBom=false`——`QJsonDocument::fromJson` 不吃 BOM，与其 task.json 约定一致） |
| 恢复引擎 | §4.3 原子三步 + hash 校验 + `_restore_tmp` 探测 |
| 六道防线 | §9 全部 |
| 回退界面 | §5 master-detail 对话框设计（列定义/统计列/明细表/Tooltip/列宽持久化/交互），DSH 的 CHistoryDialog 照此实现，列差异见 15.2 |
| 回退告知注入 | notice.json 机制 + 注入文案（DSH 已有 `promptWithRecord` 管线，接入点现成） |

### 15.2 DSH 侧映射（挂点/参数差异）

| 本方案概念 | AutoCode 挂点 | DSHAgentManage 映射 |
|---|---|---|
| 备份库根 `a_sBackupsRoot` | `<工程>/.autodev/backups`（工程级，跨任务共享去重） | `Execute\Task\<taskId>\backup`（**任务级**，与 DSH 原设计位置一致；多任务共享 workDir 时各任务库独立，无跨任务去重——如要共享去重可改挂 workDir 侧统一库，删除语义需按 owner=taskId 过滤，两者皆可，默认随原设计任务级） |
| 源码根 `a_sSourceRoot` | 工程根 | workDir |
| 过滤策略 `m_pfFilter` | 排除清单（`BackupExcludeDirs`，顶层目录级） | DSH 原设计的**扩展名白名单 + kSkipDirs + 10MB 上限**（DSH §4 整表沿用，改写成谓词注入） |
| `kind=stage` 触发 | `RunCurrentStage` 改码阶段前（后台线程） | **无对应**（DSH 无阶段状态机）——不产生 stage 版本 |
| `kind=turn` 触发 | `SubmitAdhoc(a_bReadOnly=false)` 前（同步） | `beginRecordTurn()` 三处调用点（start/sendPrompt/restartTaskProcess）——DSH **每轮**都拍（其提示词均可改码，无只读轮区分；若某轮确知只读可自行跳过） |
| `owner` | 任务 id / `"global"` | 恒 = taskId |
| `prompt` 字段 | 助手轮提问（截 2000） | 本轮提示词全文（截 2000；列表列显 40） |
| 回退 UI 入口 | 任务列表「回退[▼]」+ 助手栏「↶[▼]」 | DSH 原设计：历史对话框（CHistoryDialog）——列表列用 §5.3 规格 + DSH 特有「行数 ±」列（P3，经 `SetMetaField("stats",…)` 存入 meta，替代其 history.json 的 stats 字段） |
| 历史条目状态（normal/reverted/failed/pruned/noBackup） | 本方案暂无（P3 可加） | DSH 保留该 UX：回退后对 meta 调 `SetMetaField("state","reverted")` 即可（取代其 history.json 全量重写）；`noBackup`=轮前 Backup 返回 0 的轮 |

### 15.3 ref 链机制的裁撤清单（DSH 原设计 → CAS 后删除）

| DSH 原机制 | 处置 |
|---|---|
| `ref` 指针（内容跨快照引用） | **删**——CAS hash 寻址天然取代 |
| `state.json` 的 `base` 指针 | **删**——CAS 每版独立，无「diff 基准」概念 |
| 重定基线 rebase（物化+改写后续 manifest+磁盘峰值） | **删**——`PurgeOwner`/GC 取代（任意删版本，无峰值） |
| `guard` 独立目录/单实例/撤销后删除 | **并入** `kind=rollback-pre`（普通版本进列表，可再回退=撤销，无需独立生命周期） |
| 回退后 `QFile::setFileTime` 还原 mtime（防 stat 误判全量重拷） | **删**——hash 判定与 mtime 无关（manifest 的 `m` 字段仅用于预检警示，非判定） |
| size\|mtime 判等（漏改风险：FAT 2s 粒度/保 mtime 工具） | **删**——一律 hash，正确性换读取成本（DSH 原 §5.6 的 CRC 兜底议题随之消失） |
| `journal`（guard-done→restoring→done 崩溃日志） | **并入** `_restore_tmp` 残留探测（§4.4）——meta/文件系统即状态 |
| `history.json`（轮次索引，全量重写） | **删**——meta 文件即索引（`List` 扫 `*.meta.json`）；行数统计等扩展字段经 `SetMetaField` 进 meta |
| guard 撤销专用流程（undoRollback） | **简化**——「回退到 rollback-pre 版本」走通用回退即可 |

### 15.4 DSH 改造实施步骤（建议序）

1. 拷 `[PortableCore]` 段（含 zstd 工具函数）入 DSH 工程；构造传 `a_bBom=false`，注入白名单谓词；
2. `beginRecordTurn` 挂 `Backup("turn", taskId, "", prompt 截 2000, 0)`（同步，投递前完成）；失败→该轮 `noBackup` 态 + 日志警告（其原 §5.1 语义）；
3. `finishRecordTurn` 挂轮末统计（文件数经 `Diff` 直得；行数 ± 多重集 diff 按 DSH 原 §3.2，老内容从 store 按 hash 解压取）→ `SetMetaField("stats",…)`；
4. CHistoryDialog 按 §5 实现（列：# / 时间 / 提示词摘要 / 文件 改X增Y删Z / 行数 ± / 状态）；右表明细同 §5.4；列宽持久化随其配置机制（AppSettings）；
5. 回退：guard → `Backup("rollback-pre",…,target)`；恢复走 `Restore`；`state=reverted` 标记；`promptWithRecord` 注入回退告知（notice.json 或任务级标志，DSH 侧二选一，语义同 §6.3）；
6. 若 DSH 已按 ref 链实施过：旧 `L*` 快照目录作为 legacy 共存（`List` 标 legacy 可回退走旧恢复路径），或一次性脚本迁移（读旧 manifest 把内容物化入 store）——二选一，默认共存。
