# 测试沙箱接入开发指南

> 版本：v1（2026-11-01，配合 AutoCode 沙箱动态库化改造）
> 读者：想为 AutoCode 开发/接入新测试沙箱（动态库形态）的开发者。
> 参考实现：`sandbox/` 下的 GhostSandbox（内置幽灵沙箱，首个落地）。

---

## 1. 架构总览

```
AutoCode.exe（宿主）
  │  CMainWindow / CProjectExplorerPanel / CMcpAskServer
  │      │ 全部经门面（不再直接依赖任何沙箱实现）
  ▼
CSandboxHost（宿主门面，sandbox/CSandboxHost.*，exe 内）
  │  启动时读 config.ini [Sandbox] Type → QLibrary 全路径加载
  │  TestSandbox\<Type>.dll → resolve C ABI → 转发调用
  ▼ ────────────── C ABI（sandbox/SandboxAbi.h，唯一边界）──────────────▶
TestSandbox\
  ├─ GhostSandbox.dll          ← 沙箱 A（= 原内置幽灵沙箱整体）
  │   └─ GhostSandbox\         ← A 的私有目录（依赖 + 自有配置）
  ├─ <YourSandbox>.dll         ← 你要开发的新沙箱
  │   └─ <YourSandbox>\
  └─ ...
```

要点：

- **一沙箱一库一目录**：`TestSandbox\<Type>.dll` + 同名文件夹。dll 文件主干名
  必须等于 `sbx_id()` 返回值（宿主按 `[Sandbox] Type` 拼路径加载）。
- **缺失优雅降级**：dll 缺失/ABI 不符/加载失败时，沙箱整体不可用
  （`sandbox_*` 命令回错误文本），主程序其余功能不受影响——便携部署
  允许目标机器只拷了部分沙箱。
- **切换时机**：设置页「测试沙箱 → 沙箱类型」下拉（枚举 TestSandbox\*.dll），
  保存 `[Sandbox] Type`，**重启后生效**（运行中不热切）。
- **命令通道不变**：Agent 侧仍是 `sandbox_*` MCP 工具（claude 后端）与
  `AutoCode.exe --sandbox <cmd>` CLI（其余后端），经命名管道进主实例后
  由 Host 转给当前沙箱的 `sbx_execute`。**新沙箱只需实现命令语义**，
  Agent 提示词注入、管道桥接、线程池分发全部复用宿主既有设施。

## 2. C ABI 参考（SandboxAbi.h 摘要）

全部 `extern "C"`、字符串一律 UTF-16 `wchar_t*`。
`SBX_ABI_VERSION` 当前为 **1**（首个被调函数必须是 `sbx_abi_version`）。

### 2.1 元信息（加载探测）

| 函数 | 说明 |
|---|---|
| `uint32_t sbx_abi_version()` | 必须返回 `SBX_ABI_VERSION`，否则宿主立即卸载 |
| `const wchar_t* sbx_id()` | 沙箱 id（= dll 主干名，如 `GhostSandbox`） |
| `const wchar_t* sbx_display_name()` | 设置页下拉显示名 |
| `const wchar_t* sbx_description()` | 一句话能力描述（tooltip） |

元信息返回串为**静态串**（进程生命期有效），宿主不释放。

### 2.2 生命周期

| 函数 | 线程 | 说明 |
|---|---|---|
| `bool sbx_start(const wchar_t* json_cfg)` | 主线程 | 初始化+启动；false=失败置不可用 |
| `bool sbx_reload_config(const wchar_t* json_cfg)` | 主线程 | 设置页保存后热应用 |
| `void sbx_set_project_root(const wchar_t* root)` | 主线程 | 打开/切换工程（空串=无工程） |
| `void sbx_readopt_project_windows()` | 主线程 | 跨实例续收纳钩子（无此语义可空实现） |
| `void sbx_shutdown()` | 主线程 | 停止并还原全部；退出前必调；幂等 |

`json_cfg` 为宿主 `[Sandbox]` 通用键的 JSON 序列化：

```json
{"Enable":true,"AutoGhost":true,"Record":true,"Fps":5,"RetainDays":7}
```

沙箱**私有配置**放 `TestSandbox\<Type>\` 自读，不得要求宿主转发。

### 2.3 命令通道（核心）

```c
wchar_t* sbx_execute(const wchar_t* cmd, const wchar_t* json_args, bool* ok);
void     sbx_free(wchar_t* p);
```

- **可长阻塞**（UIA 遍历/截图/同步点击等）。宿主保证在工作线程调用
  （线程池 + MTA COM），并支持多线程并发；实现方内部自行串行化。
- 返回多行文本（给 Agent 看的）；`*ok` = 命令整体成败。
- **返回串由沙箱分配，宿主用毕必须 `sbx_free` 归还**——两侧 CRT 可能不同，
  禁止跨界 `free/delete`。
- 标准命令集（宿主与 Agent 提示词已按此约定，建议全实现；未知命令回
  错误文本而非崩溃）：

| cmd | 参数 JSON | 语义（幽灵沙箱口径，供对齐） |
|---|---|---|
| `status` | `{}` | 沙箱概况（开关/收纳数/录像状态） |
| `windows` | `{}` | 在册窗口清单（hwnd/pid/exe/标题） |
| `record_on` / `record_off` | `{}` | 录像总开关 |
| `restore_all` | `{}` | 还原全部 |
| `launch` | `{"exe":"...","args":"..."}` | 主进程代启动被测程序（防进程链断裂） |
| `capture` | `{"hwnd":"...","path":"..."}` | 离屏截图（PNG），返回路径 |
| `click` | `{"hwnd":"..","x":n,"y":n,"dbl":b,"right":b}` | 消息级点击 |
| `drag` | `{"hwnd":"..","x1..y2":n,"ms":n}` | 消息级拖动 |
| `type` | `{"hwnd":"..","text":"..."}` | 逐字符输入 |
| `keys` | `{"hwnd":"..","keys":"ctrl+s"}` | 组合键 |
| `command` / `button` | `{"hwnd":"..","cmd":n}` | WM_COMMAND / BM_CLICK |
| `tree` | `{"hwnd":".."}` | UIA 控件树文本转储 |
| `add` / `restore` / `close` | `{"hwnd":".."}` | 手工收纳/还原/关闭 |

非 GUI 沙箱（如 microVM 类）可对 GUI 命令返回
`[not-supported by <id>: <cmd>]`（ok=false），并在 `sbx_description`
里写明能力面——宿主与 Agent 均容忍部分命令不可用。

### 2.4 状态查询

`sbx_rows_json`（收纳表 JSON，须 sbx_free）、`sbx_record_dir` /
`sbx_shot_dir`（静态串）、`sbx_enabled`、`sbx_recording_on`、`sbx_fps`、
`sbx_ghosted_count`、`sbx_is_agent_born_pid`。无对应概念的返回安全空值。

### 2.5 豁免登记 / 手工根

| 函数 | 说明 |
|---|---|
| `void sbx_register_user_root(uint32_t pid, void* h_process)` | 用户主动启动的进程豁免；**hProcess 句柄所有权移交沙箱**（持有到进程退出再关闭；不支持豁免也必须 CloseHandle，防泄漏） |
| `void sbx_add_manual_root_pid(uint32_t pid)` | 手工根（该 pid 及其后代视同 Agent 树） |

### 2.6 管理对话框

```c
void* sbx_create_dialog(void* parent_qwidget);   // QDialog* 以 void* 过界
```

- 返回 dll 内 `new` 出来的 `QDialog`（parent=宿主主窗口）；无管理界面返回
  `nullptr`。
- 对话框内部（刷新定时、信号连接、样式）全部留在 dll 内；宿主只
  `setAttribute(WA_DeleteOnClose)` + `show()`。同一进程同一 Qt 运行时，
  跨界传 `QWidget*/QDialog*` 指针是安全的。

## 3. 新沙箱接入步骤（C++ / Qt，CMake）

1. **建目录**：`sandbox/` 旁新建实现文件（建议 `sandbox/MySandbox/*.cpp`
   或平铺均可），ABI 适配层一个文件（参考 `sandbox/CGhostSandboxEntry.cpp`，
   约 250 行可套用）。
2. **CMake 添加 target**（照抄 GhostSandbox 段）：

   ```cmake
   add_library(MySandbox SHARED
       sandbox/SandboxAbi.h
       sandbox/MySandboxEntry.cpp     # ABI 适配
       ...实现文件...
   )
   target_include_directories(MySandbox PRIVATE ${CMAKE_CURRENT_SOURCE_DIR} ...)
   target_link_libraries(MySandbox PRIVATE Qt6::Core Qt6::Gui Qt6::Widgets ...)
   set_target_properties(MySandbox PROPERTIES
       WINDOWS_EXPORT_ALL_SYMBOLS ON      # 便于单测直调内部类（可选）
       RUNTIME_OUTPUT_DIRECTORY         ${CMAKE_CURRENT_SOURCE_DIR}/Execute/TestSandbox
       RUNTIME_OUTPUT_DIRECTORY_RELEASE ${CMAKE_CURRENT_SOURCE_DIR}/Execute/TestSandbox
   )
   add_custom_command(TARGET MySandbox POST_BUILD
       COMMAND ${CMAKE_COMMAND} -E make_directory "$<TARGET_FILE_DIR:MySandbox>/MySandbox"
       COMMAND ${CMAKE_COMMAND} -E copy_directory
           "${CMAKE_CURRENT_SOURCE_DIR}/sandbox/assets/MySandbox"
           "$<TARGET_FILE_DIR:MySandbox>/MySandbox"
   )
   ```

3. **导出 ABI**：直接 `#include "SandboxAbi.h"`（头里已带
   `__declspec(dllexport)`），逐函数实现。字符串分配/释放配套实现
   `sbx_free`（参考 CGhostSandboxEntry.cpp 的 `Q2W`）。
4. **私有目录**：资产正本放 `sandbox/assets/MySandbox/`（README +
   manifest.json + 依赖），构建同步到 `TestSandbox\MySandbox\`。
   运行期定位自己的私有目录：取宿主传入路径不便，直接
   `GetModuleFileNameW(hModuleOfSelf)` 拼（参考 GhostSandbox 的做法演进；
   首版 GhostSandbox 无外部依赖故未实现定位函数，接入方按需自取）。
5. **单测**：仿 `test_sandbox`——`qt_add_executable` + 链接你的 dll
   （import lib），**注意**：Windows 加载器按 *exe 所在目录* 找 dll，
   需 POST_BUILD `copy_if_different "$<TARGET_FILE:MySandbox>" 到测试输出目录`；
   测试若把自身 exe 拷到 `%TEMP%` 做夹具，**部署清单必须带上 dll**
   （见 `tests/test_sandbox.cpp` 的 `DeploySelfHost`，曾因漏拷导致
   ctest 环境必挂）。
6. **设置页**：无需改代码——下拉自动枚举出你的 dll。
7. **验证清单**：
   - [ ] `python ctypes` 冒烟：22 个 ABI 符号齐全、`sbx_abi_version()` 匹配；
   - [ ] 宿主启动日志无 `[sandbox] load failed`；
   - [ ] 功能菜单 → 测试沙箱：能打开你的管理对话框（若实现）；
   - [ ] Agent 发 `sandbox_windows` / 你支持的核心命令：通道通。

## 4. 以 Rust（cdylib）实现同一 ABI —— 已落地参考：MsbSandbox

首版落地代码在 `msbsandbox/`（Cargo 工程），与本文档约定完全一致，
接入新 Rust 沙箱时直接参照：

| 关注点 | MsbSandbox 的解法（msbsandbox/src/lib.rs）|
|---|---|
| 导出 | `#[no_mangle] pub extern "C"`（x64 下与宿主 `extern "C"` 无修饰差异，ctypes/QLibrary 均可解析） |
| 返回串内存 | **CoTaskMemAlloc/CoTaskMemFree**（ole32）——两侧 CRT 不同边界的终极解；`wide_out()` 分配 +NUL，`sbx_free` 回收 |
| 静态串（id/description） | `static OnceLock<Vec<u16>>` 泄漏一次，返 `as_ptr()` |
| async SDK | 全局 `OnceLock<tokio::Runtime>`，`sbx_execute` 内 `block_on`（阻塞语义与契约③一致） |
| 私有目录定位 | `GetModuleHandleExW(FROM_ADDRESS, 本 dll 任一函数地址)` + `GetModuleFileNameW` |
| 环境探测 | `LoadLibraryW("WindowsHypervisorPlatform.dll")`+`WHvGetCapability`：WHP 未启用时 `sbx_start` 返 0 并附启用指引 |
| 便携 runtime | SDK 的 `set_sdk_msb_path`/`set_sdk_libkrunfw_path` 钉进私有目录 + `MSB_HOME` 隔离状态库 |
| GUI 命令 | 统一 not-supported 文本 + 指路 GhostSandbox（Agent 可自判） |
| 裁剪依赖 | `default-features=false, features=["local","net","download-binaries"]`（去 cloud/keyring） |

命令面扩展：MsbSandbox 新增 `vm_exec/vm_stop/vm_write/vm_read` —— ABI 的
`cmd` 是自由字符串，宿主管道透传，无需改 AutoCode 即可加新命令；
`--sandbox` CLI（SandboxCli.cpp）的已知命令表如需同步扩展再动 exe。

构建：`cmake --build build --target MsbSandbox`（需 Rust 工具链；首次联网拉
crates，已配 rsproxy 镜像；SDK `download-binaries` 自动安装 runtime 到
`~/.microsandbox`，构建后自动同步到 `TestSandbox/MsbSandbox/runtime/`）。
注意：cargo 中间产物固定走 **E:\msb-target** 短路径（长路径下 cc-rs 调
MSVC lib.exe 报 1104）；msb.exe 静态导入 `winhvplatform.dll`（WHP 未启用
的机器上它启动即 0xC0000135，属预期）与 `libkrunfw.dll`（bin 旁须有副本）。
详见 `msbsandbox/README.md` 与 `TestSandbox/MsbSandbox/README.txt`。

## 5. 版本兼容策略

- **ABI 变更纪律**：新增函数 → 尾插符号，`SBX_ABI_VERSION` 不变（宿主按
  符号存在性渐进探测）；**修改/删除签名或语义** → 版本 +1，宿主拒绝加载
  旧库（`sbx_abi_version` 不匹配即卸载），发布说明必须标注。
- 宿主永远先 `sbx_abi_version()` 再碰其它符号——这是唯一闸门。
- `manifest.json`（私有目录内）仅作人工核对与文档同步，运行期不读。

## 6. 常见问题

**Q1 dll 放好了但设置页枚举不到？**
枚举要求 `sbx_abi_version`/`sbx_id`/`sbx_display_name` 三个符号齐全且版本
匹配；用 Dependencies/ctypes 自查。另查 dll 的依赖是否可解析（宿主进程
的 DLL 搜索序：exe 目录 → 系统 → PATH；**TestSandbox\ 子目录不在搜索序**，
依赖 dll 请放私有目录并显式加载，或静态链接进沙箱库）。

**Q2 测试里链接 dll 的 exe 拷到别处就起不来（0xC0000135）？**
Windows 按新 exe 所在目录找依赖；CWD 兜底仅偶尔凑效。部署夹具必须把
沙箱 dll 一并拷贝（见 test_sandbox 的 DeploySelfHost 教训）。

**Q3 沙箱里想弹自己的 UI？**
可以（Qt 或原生均可，`sbx_create_dialog` 返回），但**绝不允许沙箱在非
用户主动触发时弹出可见窗口**——用户正在用电脑（见 CLAUDE.md 弹窗纪律）。

**Q4 GhostSandbox 的 exe 签名链？**
构建后 SIGNED 输出由本机签名钩子处理；新增 target 若被安全软件在
`%TEMP%` 类目录查杀，优先给测试夹具用已签名 exe 且避免改镜像名。
