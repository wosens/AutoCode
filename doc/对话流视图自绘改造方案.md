> 版本：v1.0（实施级设计稿，自包含——新会话无需历史对话即可实施）
> 日期：2026-10-16
> 前序：一期（2026.09.04）子线程 Markdown 预排版 `CMarkdownPreloader`；二期（2026-10-16，v4.3.379）视口惰性排版 `SetAssistantTextDeferred` + 工具卡懒重建，载档 1.8s→0.54s（3.3×）、远跳 1.7s→0.15s（11×）。本稿为三期：换渲染架构，收益目标是「打开任意长度会话首帧 < 300ms、滚动恒流畅、内存与已滚过内容无关」。

## 1. 背景与现状

### 1.1 现有架构（一、二期之后）

```
CExecutionPanel
 └─ CMessageView（QScrollArea + QVBoxLayout + 内容 QWidget）        ← 视图=滚动容器
     └─ CMessageBlock × N（QWidget，每条消息一个）                    ← 件=消息
         ├─ Assistant：QLabel(speaker) + QTextBrowser(setMarkdown)  ← 富文本=完整编辑器栈
         ├─ ToolUse  ：QToolButton(头) + 展开区 QPlainTextEdit×2N     ← 折叠卡=子控件树
         └─ Event/System/Error：QLabel 等
CStreamPresenter（每任务/每助手一个）                                 ← 数据+件+窗口
 ├─ m_aBlocks   QList<SBlockData>（唯一正本，落盘 chat.json/assistant.json）
 ├─ m_aWidgets  并行件列表 ↔ 数据下标 [frontier, frontier+n)
 └─ 窗口机制：初始 200 件 + 到顶/到底分轮补建 + 远跳整窗跳建（EnsureCoverage）
CMarkdownPreloader（全局单例）                                        ← 子线程 QTextDocument 预排版
```

二期之后批量建件路径已把「正文排版」挪出主线程且推迟到视口带，**剩余成本全部在 widget 本身**：

| 成本项 | 位置 | 二期后是否仍付 |
|---|---|---|
| QWidget 创建/构造（每件 ~几十 子对象） | 主线程 | **是**（200 件/次） |
| polish/show/样式表匹配 | 主线程 | **是** |
| QVBoxLayout 几何（每帧全树 adjustSize） | 主线程 | **是**（O(N)，N=活件数） |
| QTextBrowser 实例（document+cursor+undo+滚动条+输入控制） | 每件常驻内存 | **是**（材化带内） |
| 事件分发（每件 30+ 子件都进事件链） | 常驻 | **是** |
| Markdown parse+初排版 | 子线程 | 否（预排版） |
| 全量正文排版 | — | 否（视口惰性） |

结论：widget-per-message 的成本下限 = 200 件 × (构造+polish+布局)，无论正文排不排。这是架构性天花板，继续在现架构上调优收益递减。

### 1.2 触发本次立项的实测（二期 A/B 探针，2026-10-16）

场景：200 条 3KB Markdown + 60 条工具（900×640 视图，Release/offscreen）：

| 指标 | 一期前 | 二期后 |
|---|---|---|
| 载档重建（Rebuild 收敛） | ~1.8s | ~0.54s |
| 远跳（EnsureCoverage(0)） | ~1.7s | ~0.15s |

0.54s 里 >80% 是件创建+布局（正文排版已异步）。真实档（×52 合并卡、10KB 思维链、多助手）更长；且多助手页虽已「隐藏 Tab 全惰性」，切 Tab 瞬间仍要付整窗件创建。

## 2. 调研结论（GitHub 成熟项目怎么做）

所有「海量聊天流流畅显示」的成熟项目**全部放弃 widget-per-message**：

| 项目 | 场景 | 架构 | 可借鉴点 |
|---|---|---|---|
| [Chatterino2](https://github.com/Chatterino/chatterino2)（Twitch 客户端，C++/Qt Widgets，2.6k★） | 每秒百级消息滚动 | **纯 paint 自绘，零子 widget**（`ChannelView::paintEvent`） | ① `layoutVisibleMessages()` 只排版可视消息；② `RequiresLayout/RequiresBufferUpdate` 脏标记——排版结果缓存成 QPixmap，重画=bitBlt；宽度变化不立即重排，滚到才排；③ `LimitedQueue` 固定容量环形队列 |
| [Telegram Desktop](https://github.com/telegramdesktop/tdesktop)（33k★） | 无限历史会话 | 自绘 + 每项高度缓存 + 可视区回调 | `ListDelegate::listSource(aroundId, limitBefore, limitAfter)` 数据层「围绕锚点取窗口」接口（与我们窗口机制同源）；delegate 虚接口按条目类型分发 paint |
| [Qt Creator](https://github.com/qt-creator/qt-creator)（官方） | ① 输出面板 ② 帮助富文本 | ① `QPlainTextEdit + maximumBlockCount`；② litehtml 替换 QTextBrowser（`src/plugins/help/litehtmlhelpviewer.cpp`，同插件保留 textbrowser 版可对比） | 行式日志的最快官方姿势；富文本渲染引擎可替换性佐证 |
| [klogg](https://github.com/variar/klogg)（3.5k★） | GB 级日志秒开 | `QAbstractScrollArea` 自绘文本行，只画可视区 | 只画可视区的极简范本 |
| [md4c](https://github.com/mity/md4c)（1.5k★） | — | Qt `setMarkdown` 内置解析器（纯 C） | 佐证：**慢的从来不是 Markdown 解析，而是 QTextDocument 布局 + widget 树**。解析层无需更换 |

两条可落地路线（§4 选型）：

- **路线 A**：`QListView + QAbstractItemModel + 自定义 delegate paint`——Qt item view 框架自带**虚拟化**（只有可视区附近的 item 被 paint/sizeHint）、滚动、选择框架；交互经 `editorEvent`。
- **路线 B**：Chatterino 式**完全自绘 QWidget**（paintEvent + 自管滚动几何）——控制力最强，但滚动条/锚定/DPI/触摸惯性全要自写。

## 3. 目标与非目标

**目标**

1. **G1 打开即得**：任意长度会话（含万条级）载档→首帧可交互 < 300ms；
2. **G2 滚动恒流畅**：视口带命中时单帧 < 16ms（无件创建、无全树布局）；
3. **G3 内存有界**：常驻内存与「已滚过的内容量」无关（文档池 LRU 上限）；
4. **G4 交互等价**：折叠/展开、复制、跳转、跟随尾部、合并卡、diff 着色、speaker 标注全部保留（视觉允许 ≤5% 差异）；
5. **G5 零迁移**：`SBlockData`/`BlockToJson`/chat.json/assistant.json 落盘格式**一字不动**；旧档直接打开。

**非目标**

- 不改数据采集/合并判定逻辑（谁和谁合并的规则原样迁移）；
- 不引入 QML/WebView/litehtml（二进制与依赖不变，QTextDocument 渲染保真）；
- 不做行内富文本编辑（流是只读的）；
- 不追求与旧版像素级一致（QTextBrowser 与 QTextDocument::drawContents 的边距差 ≤2px 可接受）。

## 4. 总体架构与选型

### 4.1 选路线 A（QListView 框架），B 作为逃生舱

| 维度 | A：QListView+delegate | B：Chatterino 纯自绘 |
|---|---|---|
| 虚拟化/滚动/可见性 | 框架自带 | 全自写（~1500 行） |
| item 高度协议 | sizeHint 现成 | 自管几何+锚定 |
| 风险 | QListView 个别行为（见 §11） | 工作量×1.6 |
| 与现有测试桩 | 模型层可单测 | 只能整体 UI 测 |

A 的框架成本可控且模型层可独立单测，**定 A**；若实施中发现 QListView 滚动条行为无法驯服（§11-R3），delegate/池/模型三层可原样搬到 B 的画布上（三者都不依赖 QListView 具体类型——这是分层设计约束）。

### 4.2 分层

```
┌────────────────────────────────────────────────────────────────────┐
│ CExecutionPanel（不动）                                              │
│   ├─ CStreamPresenter ←— 保留：数据正本/落盘路由/流式合并；           │
│   │     视图职责移交给新层（§9.2 职责重划）                           │
│   ▼                                                                │
│ CChatModel : QAbstractListModel        ← §5 显示条目模型            │
│   SDisplayItem[]（合并后）；SBlockData 正本仍在 presenter            │
│   职责：原始块→显示条目折叠、增删改信号、数据↔条目下标映射、          │
│         交互状态（展开/选择模式，内存态不落盘）                       │
│   ▼ index                                                          │
│ CChatListView : QListView              ← §6 视图                    │
│   职责：跟随尾部、滚动锚定补偿、右键菜单、选择覆盖层宿主、跳转        │
│   ▼ paint/sizeHint/editorEvent（per 可视 item）                     │
│ CChatDelegate : QAbstractItemDelegate  ← §7 渲染与交互（核心）      │
│   分 kind 绘制；高度缓存；点击 hit-test                              │
│   └─ CChatDocPool（QTextDocument LRU 池）← §7.3 Assistant 富文本    │
│        └─ CMarkdownPreloader（现有，原样复用：子线程排版产物入池）    │
└────────────────────────────────────────────────────────────────────┘
```

各层不依赖上层具体类型（delegate 只认 QModelIndex 的 role 数据与 doc 池）——满足逃生舱约束。

### 4.3 显示条目 = 合并后的呈现单位（关键概念）

现状合并在**件层**做（`CStreamPresenter::TryMergeWidget` 把连续 ToolUse 并进上一张卡、连续 System 行并进组卡）。三期合并在**模型层**做：

```
原始块序列（presenter.m_aBlocks，SBlockData×N，不动）
        │ CChatModel::rebuild()/append() 折叠
        ▼
显示条目序列（m_aItems，SDisplayItem×M，M ≤ N）
   Assistant  → 1:1
   ToolUse    → 连续区段合并为 1 条目（span=[iBegin,iEnd)，entries 持各区段快照）
   System     → 连续区段合并为 1 组卡条目
   Event/Error→ 1:1
```

`SDisplayItem`（内存结构，不落盘）：

```cpp
struct SDisplayItem {
    CMessageBlock::EKind eKind;        // 复用现有枚举（迁移期兼容）
    int  iBegin, iEnd;                 // 原始块区间 [iBegin,iEnd)（1:1 时 iEnd=iBegin+1）
    QString sText;                     // Assistant/Event 文本（浅拷贝 SBlockData）
    QString sEventKind, sBackend;
    // —— ToolUse 合并卡 ——
    struct STtlEntry { QString sTool, sInput, sResult; };   // 各区段快照（结果回填改这里）
    QList<STtlEntry> aTools;
    // —— System 组卡 ——
    QStringList aSysLines;
};
```

- 数据下标 → 条目：模型内有序数组 + 每条目 iBegin/iEnd 二分（或加载时一次线性映射表 `m_aIdx2Item`，append 增量维护）；
- **结果回填** `BackfillResult`：presenter 写 SBlockData 后调 `model->BackfillResult(数据下标, 结果)` → 映射条目 → 改 aTools[k].sResult → `dataChanged(条目, {ToolResultRole})`（**不改高度**——折叠态；展开态才可能变高）。

## 5. 模型层 `CChatModel`（QAbstractListModel）

### 5.1 Role 表（一次定死，跨层协议）

| Role | 类型 | 内容 | 消费者 |
|---|---|---|---|
| `KindRole` | int | EKind | delegate 分发 paint |
| `TextRole` | QString | Assistant 正文 Markdown / Event·System·Error 文本 | delegate/复制/搜索 |
| `SpeakerRole` | QString | 产出后端名（原 sBackend） | delegate 画 speaker 行 |
| `ToolEntriesRole` | QVariantList | aTools（sTool/sInput/sResult） | delegate 工具卡 |
| `EventKindRole` | QString | 事件徽章 kind | delegate 配色 |
| `CollapsedRole` | bool | 折叠态（工具卡/System 组卡） | delegate 头行/展开区；**setData 可写** |
| `SelectModeRole` | bool | 该条目处于选择覆盖模式（§8） | 视图建覆盖层 |
| `Qt::SizeHintRole` | QSize | 高度缓存条目失效通道 | — |

交互态（Collapsed/SelectMode）放模型而非全局 map 的理由：`dataChanged` 天然驱动重绘与高度失效，免掉自管脏通知；不落盘约束由「这两个 role 不进 `BlockToJson`」保证（序列化只走 presenter 的 SBlockData）。

### 5.2 增量操作（与 presenter 的接缝）

| presenter 侧事件 | 模型侧调用 | 复杂度 |
|---|---|---|
| 载档 SetBlocks + Rebuild | `beginResetModel` → 重建 m_aItems（一次线性合并）→ `endResetModel` | O(N) |
| 流式 Append 一条 | `AppendBlock(SBlockData)`：尾部可并入 → `dataChanged(尾条目)`；否则 `beginInsertRows` 添 1 | O(1) 摊销 |
| BackfillResult | §4.3 所述 | O(log M) |
| 撤销到某轮（撤销功能） | 按数据下标截断 → `beginRemoveRows` 批量删 | O(截断量) |

**窗口机制退役**：模型持全量 m_aItems（内存=原始数据的浅拷贝引用，约 +80B/条），QListView 天然只渲染可视区——`k_iViewInitial/k_iViewPrepend/EnsureCoverage/JumpRebuild/PrependOlder/AppendNewer` 全部不再需要（§9.3 保留接口壳转发 scrollTo）。

### 5.3 模型可单测（不含 UI）

`tests/test_chatmodel.cpp`：载档折叠比例、append 增量合并、回填映射、截断撤销、dataChanged 信号序列——全部无 QWidget 依赖。

## 6. 视图层 `CChatListView`（QListView）

```cpp
class CChatListView : public QListView {
    // 基本盘
    //   setUniformItemSizes(false)   —— 高度各异
    //   setVerticalScrollMode(ScrollPerPixel)、水平 ScrollBarOff
    //   setSelectionMode(NoSelection) —— 选择由 §8 覆盖层承担
    //   setItemDelegate(&m_Delegate)
    //   setResizeMode(Adjust)——sizeHint 变化即时重排（配合锚定补偿）
public:
    void SetModel(CChatModel* a_pModel);
    void JumpToItem(int a_iItem, PositionAtTop);     // scrollTo：O(1)（估高已全量）
    void FollowTail(bool a_bOn);                      // 跟随尾部（复用现启发式：新行且用户在底→滚底）
signals:
    void sigBottomReached();                          // 语义保留（到底加载无了，仅给"回到底部"箭头用）
private slots:
    void OnRowsInserted();                             // 尾部新条目 + 跟随态 → scrollToBottom
    void OnSizeHintCorrection(int a_iItem, int a_iDeltaY);   // §7.4 高度校正锚定补偿
private:
    void contextMenuEvent(QContextMenuEvent*) override;      // 条目级右键：复制正文/复制工具明细/全选折叠/展开
    void resizeEvent(QResizeEvent*) override;                // 宽度变化 → delegate 宽度失效（§7.4）
    // 选择覆盖层宿主（§8）：QHash<条目,QPointer<QTextBrowser>>
};
```

**滚动条一次成型**：载档时模型对每条目同步给**估高**（§7.4，纯算术，万条 <30ms），range 立即确定；doc 材化后的真实高度只做**个条目校正**（+锚定补偿），滚动条不再大幅呼吸（这是对二期经验「估高先占位、落地后校正」的直接继承）。

## 7. `CChatDelegate`（核心：渲染 + 交互）

### 7.1 绘制分发（paint 全 painter，零子 widget）

| 条目类型 | paint 内容 | 高度 |
|---|---|---|
| Event | 彩色圆点 + kind 文本（QStaticText 缓存） | 单行 fm |
| System/Error | 小号灰/红字；组卡=头行 + 展开时逐行 | 单行 / 行数×fm |
| Assistant | speaker 行（品牌色+后端名）+ 左侧强调条 + **QTextDocument::drawContents** | doc 高度（§7.3） |
| ToolUse 折叠 | 圆角底 + ▶ + "工具名 摘要(ElideMiddle) ×N" | 单行（现状同款） |
| ToolUse 展开 | 折叠头（▼）+ 每条目：摘要行 + 入参等宽块 + 结果块；Edit/Write **diff 红绿背景**逐行 painter | entries×行数（§7.5 截断） |

单行文本一律 `QStaticText`（解析一次常驻，重复 paint 零布局成本——Chatterino 同款手法）；省略号 `QFontMetrics::elidedText`。

### 7.2 editorEvent（交互进 paint 世界的桥）

```cpp
bool editorEvent(QEvent* ev, QAbstractItemModel* m, const QStyleOptionViewItem& opt, const QModelIndex& idx) {
    // MousePress → 命中区判定（纯几何，各类型给命中矩形，见 §13 伪代码）
    //   工具卡头行区 → model->setData(idx, !collapsed, CollapsedRole)   // 翻折叠
    //   System 组卡头 → 同上
    //   Assistant 文档区 → doc 已材化：docHitTest(anchor) → 命中链接 openUrl；
    //                      未材化：先材化（同步，可视区必已材化——见 §7.3 带宽）
    //   "展开更多"按钮区（长结果截断）→ setData 展开全部
    // MouseDoubleClick（Assistant）→ setData(SelectModeRole=true)        // §8 选择覆盖
    // Hover/Leave → 刷新 hover 行（复制按钮显隐）
}
```

`QAbstractItemView` 只把**视图级**鼠标/键事件路由给可视 item 的 editorEvent——正好是我们要的交互面，无需自管 hit-test 分发表。

### 7.3 Assistant 富文本：`CChatDocPool`（QTextDocument LRU 池）

QTextDocument **本身就是布局缓存**（一次 setTextWidth 后 drawContents 便宜），不需要 Chatterino 的 QPixmap 中转（那是它完全自绘文本才需要的）；**池化 doc + 复用预排版产物**即可：

```cpp
class CChatDocPool : public QObject {
    // 条目下标 → QTextDocument（parent=池；LRU 双向链表）
    // 材化（视口带内，±2 屏）：
    //   池命中 → 直接用（宽度不同才 setTextWidth 重排，毫秒级）
    //   池未命中 → CMarkdownPreloader::Submit(sMarkdown, estWidth, cb)   ← 现有链路原样复用
    //             cb 落地：doc 入池 + 通知 delegate 高度校正
    // 释放（6 屏外）：doc 从池摘除 delete（QString 原文仍在模型，零丢失）
    // 上限：MIN(64 docs, 合计 32MB)；超限按 LRU 逐出
};
```

- **带宽沿用二期参数**（材化 ±2 屏 / 释放 6 屏滞回），驱动从「CMessageView::RefreshMaterialization」换成「QListView 可视区回调 + 滚动节流」——`verticalScrollBar()->valueChanged` 合并 16ms 节流 + `rowsAboutToBeRemoved` 清池；
- **宽度变化**（resize/splitter）：`pool->ClearWidth(width)` → 逐 doc `setTextWidth`（分帧 8 docs/帧，同现分帧手法）→ 高度逐条校正（锚定补偿 §7.4）；
- doc 池与模型生命周期：`beginResetModel` 清池（切任务/切助手档）。

### 7.4 高度缓存与锚定补偿（滚动不跳的关键）

```
sizeHint(idx):
  h = m_aHeights[idx]                     // 缓存命中直接返回（paint 期零计算）
  未缓存 → 估高 EstimateHeight(item, width)（二期 EstimateAssistantHeight
           迁出 CMessageBlock 为自由函数；Event/System=单行公式）
           写缓存 → 返回

doc 材化/宽度重排完成：
  realH = doc->documentLayout()->documentSize().height() + 头行/边距
  Δ = realH - m_aHeights[idx]
  if |Δ| <= 1px: 更新缓存即可（不通知）
  else:
    更新缓存 → dataChanged(idx, {SizeHintRole})
    ── 锚定补偿（防视口内容跳）──
    if 该条目在视口上方（y_top < scrollValue）:
        verticalScrollBar()->setValue(scrollValue + Δ)   // 视口内容视觉零位移
```

补偿只对「视口上方条目」生效——下方/带内条目高度变化本来就推动视口内容向上/下平移一屏内的自然量，无需补（与二期「弃正文锁高度」同思想，但方向相反：现在是**变真实高度时**防跳）。

### 7.5 工具卡展开区与 diff

- 入参：`PrettyLegacyJsonLine`/`ToolSummary`（现有静态函数）产出摘要行；展开区入参画等宽灰文本（≤12 行，超出折叠为「…展开全部 N 行」交互态）；
- 结果：同上；结果尾部错误关键词（`error/失败/exception`）红字（对齐现 `SetResult` 自动展开逻辑——实时错误单条卡仍自动展开：`AppendBlock` 时按现有判定 `setData(CollapsedRole,false)`）；
- **Edit/Write diff**：沿用现 diff 生成（`RebuildToolContent` 中红绿行序列生成逻辑抽成纯函数 `BuildDiffLines(sInput,sResult)`），paint 时逐行背景带（`#3fb95022`/`#f8514922`）+ 等宽文本；
- 展开态高度：`entries × Σ(摘要+入参行+结果行)` 全公式化（无 doc），缓存同 §7.4。

## 8. 文本选择与复制（最大交互难点，两期实现）

QTextBrowser 原生拖选/部分复制在自绘世界不存在。分级交付：

**一期（常驻）：块级复制**——条目 hover 头部右侧浮「复制」小按钮 + 右键菜单：

| 条目 | 复制内容 |
|---|---|
| Assistant | Markdown 原文（`TextRole`） |
| ToolUse | `工具名 + 入参 JSON + 结果` 逐条拼文本 |
| System 组 | 全部行 |
| Event | 文本 |

**一期（补位）：选择覆盖层**——双击 Assistant 条目 → 视图在该条目 geometry 上浮一个**只读 QTextBrowser**：`setDocument(池中同一 doc)`（池保留所有权，覆盖层销毁只 hide）→ 拖选/Ctrl+C 原生可用 → Esc/复制完成/点击别处 → 移除覆盖层 + `SelectModeRole=false`。同 doc 同宽渲染，视觉无缝；**只在被双击的单条目上付出一个 QTextBrowser 的代价**——「需要时才付编辑器成本」正是本方案的纲领。

**二期（可选，视用户反馈）**：自绘选择——QTextDocument 的 `QTextLayout::lineAt` 几何 + 选择区间绘制 + `QTextDocumentFragment::toPlainText` 部分复制（Telegram 就是这么做的）。仅当用户强烈需要跨块/行内选择再做，预算 +1 天。

## 11. 风险与对策

| # | 风险 | 对策 |
|---|---|---|
| R1 | QTextDocument 非 GUI 线程约束 | 预排版产物**创建于子线程、仅主线程使用**——现有 CMarkdownPreloader 已是该语义（moveToThread 回主线程再交接），池只碰主线程 |

| R4 | 高 DPI / devicePixelRatio | QTextDocument 矢量绘制无位图问题；QStaticText 同；不引入 QPixmap 缓存故无 DPR 键 |
| R5 | 覆盖层与 delegate 事件争抢 | 覆盖层出现时 `view->setEditTriggers(NoEditTriggers)` + 覆盖层 grabMouse；Esc 快捷键退出兜底 |
| R6 | 视觉回归（边距/字体与旧版差） | QTextBrowser 与 drawContents 同源同字体，差异集中块 padding；期2 做并排截图对比页（设置里临时开关）人工过一遍 |
| R7 | 双引擎并存期 bug 双修成本 | 规则：期1-3 凡改**数据/合并逻辑**必须双引擎同改（本来就该同源）；纯渲染改动只动新引擎 |
| R8 | 内存池上限拿捏 | 64 docs / 32MB 起步 + 设置页暴露 `[View] DocPoolMax`；诊断：标题栏暂显池占用（调试构建） |

|---|---|---|

// ── delegate paint（分发骨架）──
void CChatDelegate::paint(QPainter* p, const QStyleOptionViewItem& opt, const QModelIndex& idx) const {
    const auto e = EKind(idx.data(KindRole).toInt());
    switch (e) {
    case Event:    PaintEvent(*p, opt, idx);            break;   // QStaticText+圆点
    case System: case Error: PaintSystem(*p, opt, idx); break;   // 组卡折叠/展开
    case Assistant: PaintAssistant(*p, opt, idx);       break;   // §7.3 doc
    case ToolUse:  idx.data(CollapsedRole).toBool() ? PaintToolHead(*p, opt, idx)
                                                   : PaintToolFull(*p, opt, idx);
    }
}

void CChatDelegate::PaintAssistant(QPainter& p, const QStyleOptionViewItem& opt,
                                   const QModelIndex& idx) const {
    PaintSpeakerBar(p, opt, idx.data(SpeakerRole).toString());     // 品牌色行+左强调条
    if (QTextDocument* d = m_pPool->Acquire(idx)) {                // 触材化（带内即同步命中）
        p.save(); p.translate(opt.rect.left() + k_iPadL, opt.rect.top() + k_iHeadH);
        d->drawContents(&p);                                       // 布局缓存直绘
        p.restore();
    } else {
        PaintSkeleton(p, opt);          // 未材化（带外理论不可见；防滚动极端速度闪白）
    }
}

// ── editorEvent 命中区（几何判定，无控件）──
bool CChatDelegate::editorEvent(QEvent* ev, QAbstractItemModel* m,
                                const QStyleOptionViewItem& opt, const QModelIndex& idx) {
    if (ev->type() != QEvent::MouseButtonPress && ev->type() != QEvent::MouseButtonDblClick)
        return false;
    const QPoint pt = static_cast<QMouseEvent*>(ev)->pos();
    if (EKind(idx.data(KindRole).toInt()) == ToolUse && pt.y() < opt.rect.top() + k_iHeadH)
        { m->setData(idx, !idx.data(CollapsedRole).toBool(), CollapsedRole); return true; }
    if (/* Assistant 双击 */) { m->setData(idx, true, SelectModeRole); return true; }  // §8
    if (/* Assistant 单击 & doc 已材化 */) {
        if (const QString sUrl = HitAnchor(m_pPool->Peek(idx), pt))
            { QDesktopServices::openUrl(sUrl); return true; }
    }
    return false;
}

// ── 池材化（滚动驱动，16ms 节流合并）──
void CChatDocPool::OnViewportChanged(int iVal, int iVh) {
    for (可视±2屏内未材化条目)  CMarkdownPreloader::Instance()->Submit(sText, iWidth, cb);
    for (6屏外已材化条目)        Evict(idx);          // doc 删，缓存高度保留（估高同款锁形）
}
