亮点速览

先看最值得知道的六件事

🏭 全流程自动编排 需求收集 → 需求确认 → 评审 → 设计 → 计划 → 开发 → 代码审查 → 测试，每个阶段自动调度 Claude 执行，全程无需人工盯守。
🔀 四大 Agent 后端随心切 Claude Code / DeepSeekHarness(DSH) / PIAgent / CodexHarness 四后端并列，设置页一键切换；DSH/Pi/Codex 均支持自定义网关模型条目与费用折算。
🔀 双工作流：Feature / Bugfix 新功能走「设计-计划-开发」主线；修缺陷走「根因分析-核实-修复」专线，互不拖累，各走各的最短路径。
🔄 评审驳回自动迭代 内置三道评审关卡，不通过自动打回上游阶段重做；每阶段最多重跑 3 次，超过则暂停并升级给用户，绝不无限空转。
📊 过程全透明 阶段图标条实时点亮推进；日志页完整呈现 Claude 的每句话、每次工具调用；底部实时统计费用与 token 消耗，花销一目了然。
🧠 工程记忆 guide.md 打开工程时自动扫描代码库生成架构总览，后续每次改动追加流水记录并支持一键同步，Claude 越干越懂你的项目。
📦 绿色便携 · 随手可用 单文件夹即整软件，配置随程序走；首次使用「环境安装」一键装齐 Git / Node.js / Claude Code CLI。

30 秒上手

四步跑通第一个任务

装环境（仅首次） — 菜单 功能(F) → 环境安装...，授权后自动安装 Git、Node.js 与 Claude Code CLI。
已装过可跳过；DeepSeekHarness 为可选组件，脚本结束前会询问是否一并安装（不装不影响使用）；脚本位于程序目录 install_env.bat，也可右键以管理员身份手动运行。
打开工程 — 菜单 工程(P) → 打开工程目录... 选择你的代码目录（或「新建工程目录...」从零开始）。
首次打开会自动扫描代码库生成 .autodev/guide.md（工程架构记忆），需几分钟；下次可从「最近打开」子菜单一键回到常用工程（启动时不自动加载）。
新建任务 — 左栏 新建 按钮：填任务名称、选类型（Feature / Bugfix）、写需求描述，勾选「立刻启动任务」点确定。
不勾立刻启动，则之后选中任务点「继续」再启动。
看结果 — 右栏阶段图标条逐个点亮；「日志」页看执行过程，「阶段产物」页看每阶段生成的 .md 文档，完成后工程代码即已修改。
需要纠偏时：任务运行中可在日志页下方「介入指令」框留言；要立即生效则先「暂停」改完再继续（详见「人工介入」一节）。

界面总览

一屏读懂：左管任务，右看执行

区域名称作用
1菜单栏 工程(P) 新建/打开工程、最近打开、同步 Guide；功能(F) 设置、环境安装；帮助(H) 本说明、关于。
2任务列表（当前 / 历史 Tab） 「当前任务」列本工程进行中的任务；「历史任务」列本工程已完成/失败的全部任务（存在工程自己的 .autodev/history.db，随工程走），支持右键「再次执行」。
3任务控制按钮 新建 / 继续 / 暂停 / 停止 / 回退，按钮随所选任务状态自动启用禁用。
4工程资源管理器 以工程目录为根节点浏览工程内全部文件（自动隐藏 build/.git/.vs/node_modules 等生成目录；.autodev 与 Execute 可见）；单击文件即预览（文本类进内嵌预览页但不切页），双击文本类切到预览页，exe 等非文本文件以文件所在目录为工作目录调系统默认程序运行（与 Windows 资源管理器双击一致，游戏/便携程序可正常启动），支持 Windows 式拖拽（拖出到资源管理器/聊天窗口、树内移动/复制、拖入导入），右键支持剪切/复制/粘贴/删除/改名/复制路径/「通过资源管理器打开」/「打开方式」/「添加到聊天框」等。
5阶段图标条 当前任务的阶段横向图标条（2026.09.04 起，替代旧的纵向阶段表）：每阶段一个圆形状态图标 + 短名，连接线指示推进进度——✔绿=已完成、▶蓝=进行中、✖红=失败、⏸黄=未完成、○灰=待执行；鼠标悬停显示阶段全名与状态，右键某阶段可「再次执行」（仅重跑该阶段）。整条固定一行高，纵向空间全部留给日志区。
6日志 / 阶段产物 / 助手 Tab / 文件预览 日志=任务执行对话流；阶段产物=各阶段生成的 .md 文档；助手=可开多个的独立问答助手（动态 Tab）；双击资源管理器文件生成预览页。
7费用 / Token 统计 当前任务累计费用（美元）与输入/输出 token 数。仅任务侧（2026.09.05 起任务与助手统计完全隔离），紧跟在状态图标之后（图标转圈=任务运行中、空闲色点=任务状态）；各助手自己的费用/token/请求/耗时统计在各自助手页内统计栏，同样自带状态图标（转圈=该助手运行中）。
8状态栏 当前工程路径、guide.md 状态、已载入任务数。

工作流与阶段

AutoCode 的核心：两条流水线 + 三道评审关卡

① Feature 流程（新功能，10 个阶段）

需求收集1→ 确认需求2→ 需求评审3→ 设计4→ 设计评审5→ 计划6→ 计划评审7→ 开发8→ 代码审查9→ 测试10→ ✅ 完成

② Bugfix 流程（修缺陷，8 个阶段）

需求收集1→ 确认需求2→ 根因分析11→ 根因核实12→ 修复13→ 代码审查9→ 测试10→ ✅ 完成
分组： 需求 设计 计划 实现 质检 缺陷专线

③ 评审驳回 → 自动打回重做

④ 任务状态一览

状态含义可执行操作
🟡 Pending已创建未启动继续（启动）
🔵 Running执行中暂停、停止、介入指令
⏸ Paused暂停（含迭代超限自动升级）继续（从下一阶段恢复）
⏹ Stopped被手动终止继续（续跑）、回退
✅ Done全部阶段完成（转入历史）右键「再次执行」
❌ Failed执行失败（转入历史）右键「再次执行」重试
「暂停」是阶段边界暂停：当前阶段会跑完，在进入下一阶段前停下 —— 不会产生半截产物。

功能详解

🛠 工程管理

操作说明
新建工程目录...选一个空目录新建工程，自动初始化 .autodev 并生成 guide.md。
打开工程目录...打开已有代码目录；首次打开自动扫描生成 guide.md（耗时数分钟）。
最近打开最近工程一键直达（子菜单最多 10 条，末尾「...」打开全量历史对话框，对话框顶部搜索框实时按名称/路径过滤列表）；启动时不自动加载工程，停留在空工程态由用户手动选择。
同步 Guide按 record.md 中的改动流水增量更新 guide.md（任务完成后也会自动触发，此处为手动入口）。
任务右键菜单当前任务：查看任务内容 / 移除；历史任务：查看任务内容 / 再次执行。
回退按钮打开统一回退界面：左侧记录点列表（任务阶段 / 助手轮次双粒度，增量备份），右侧文件变动明细，选中记录点后点「回退到此记录点」把工程源码回退到该时点（双击不执行回退，防误触）。回退前会先把当前现场自动快照留底，随时可再撤销回来。

📂 工程资源管理器

左栏底部的文件树：工程目录本身就是根节点（打开后自动展开），显示工程内全部文件；生成目录（build、.git、.vs、node_modules）自动整目录隐藏，保持树面干净；.autodev（任务产物/记录）与 Execute（部署产物/配置/提示词）可见可浏览。显示隐藏与备份排除互不相干：备份范围由设置页「备份排除目录」（[Backup] ExcludeDirs，默认含 build/Execute/.autodev/node_modules 等——依赖目录文件量巨大且可再生，不备份可把大工程首轮快照从几十分钟降到秒级）单独控制，与树中是否可见无关。

操作说明
双击文件 / 目录用系统默认程序打开（目录则用资源管理器打开）。
拖拽（2026.08.27 新增）与 Windows 资源管理器一致：拖出——把文件/目录（支持多选）拖到系统资源管理器即复制/移动，拖到聊天软件发送框即作为附件；树内拖动——拖到另一目录默认移动（按住 Ctrl=复制）；拖入——从系统资源管理器拖文件到树上即复制进目标目录。目标同名自动加 “(2)” 序号，目录不可拖入自身子树。
通过资源管理器打开目录直接打开该目录；文件则打开所在目录并定位选中该文件。
剪切 / 复制 / 粘贴工程内文件与目录的移动复制（粘贴有同名冲突提示）。
删除 / 改名删除有二次确认；改名弹输入框，目标已存在会拦截。
复制路径 / 复制相对路径绝对路径 / 相对工程根的路径写入剪贴板（Windows 原生分隔符）。
添加到聊天框把选中文件的路径插入「助手」提问框，向 Claude 提问时直接引用该文件。

📁 工程数据都存在哪？—— .autodev 目录

所有任务产物都落在工程自己的 .autodev/ 目录里，随工程走、可提交进版本库：

<工程根>/ └── .autodev/ ├── guide.md ← 工程架构总览（Claude 的“项目记忆”，自动生成） ├── record.md ← 全局修改流水（每次改动追加） ├── history.db ← 本工程历史任务库（随工程走；损坏自动收档重建） └── tasks/ └── <task-id>/ ← 每个任务一个私有目录，互不干扰 ├── task.json ← 任务档案（进度 / 迭代 / 费用，权威数据源） ├── assistant.json ← 助手会话档（多助手 Tab、撤销栈） ├── backups/ ← 增量备份存储（回退界面的记录点数据） └── intake.md / requirements.md / design.md / plan.md / cr.md / root_cause.md ...

📊 执行面板（右栏）

页签内容
日志任务执行的完整对话流：Claude 的分析文本、每次工具调用（Read/Edit/Bash...）及结果，底部可发「介入指令」中途纠偏（仅任务运行中可用）。折叠显示：工具调用卡片默认折叠、点击展开（Edit 红绿 diff），连续多次工具调用自动合并为一张卡（标题显示首条摘要 + ×N，展开逐条查看）；连续的系统/提示信息行合并为一个灰色折叠组（标题显示首行摘要与行数），错误行独立标红不折叠。
反向分页（2026.09.03 新增）：历史较长的会话切档/重开时初始只挂载最近 200 条消息（大幅降低切档耗时与内存），更早的消息滚动到顶部时自动加载（每次追加 100 条，视口位置锥定不动，不跳动）；提示词下拉跳转到更早提问时也会自动补齐加载。
流畅加载（2026.09.04）：历史块分小帧渐进构建（每帧限定耗时预算，不卡界面）；消息的 Markdown 排版在后台线程预渲染（界面线程只做轻量落地），切任务/切助手/滚动加载大量历史时界面保持响应。
阶段产物按阶段列出 .autodev/tasks/<id>/ 下生成的 .md 文档（需求书、设计书、计划书、审查报告...），右侧直接渲染阅读。
助手 1 / 助手 2 / …动态多助手 Tab，每个 Tab 一条独立问答会话（互不串流）：「＋」页新增助手；Tab 上 × 关闭（会话保留可恢复）；右上角 ▾ 弹出已关闭助手列表选名恢复；拖动排序、双击改名，右键彻底删除（二次确认后对话/会话链/统计永久移除，不可恢复；与 × 软关闭不同）。运行中的助手独立累计日志，切走再看也不丢。Tab 标题标记：● 运行中。
多助手并发（2026.09.03 新增）：每个助手是一个完全独立的 Agent（各自的 CLI 进程、会话链、上下文与消耗统计）。助手 A 运行中切到/新建助手 B 后发送，指令立即在 B 开始执行（B 起自己的进程），不排队、不等 A 结束；多个助手可同时亮 ● 并行干活，各自的输出落到各自的日志流。在同一助手运行中发送仍是「追加指令」（注入当前轮或本轮结束后自动续发）。
输入栏/统计栏随页走（2026.09.05 新增）：每个助手 Tab 页内自带独立实例的指令输入框、权限下拉（自动/手工/只读）、上下文/撤销/发送按钮和费用统计栏（费用前有状态图标——该助手运行中转圈、空闲灰点；含本轮 ↑↓ 实时与耗时跳动）——切助手即整套切换，各助手的输入草稿与消耗统计互不干扰；助手消耗不再并入任务统计（面板底部统计栏仅任务侧）。
文件预览资源管理器单击文件生成预览页，双击切到该页（多文件并存）。

💬 两个输入框，用途不同

介入指令（日志页下方）助手输入（各助手页内，独立实例）
对象正在运行的任务独立助手会话（每个助手自己的输入框，草稿互不干扰）
时机仅任务 Running 时可用打开工程后随时可用；该助手运行中仍可打字，发送变「➤ 追加指令」（向该助手当前轮追加，立即注入/本轮结束后自动发出）或「⏹ 停止」（只停该助手，不影响其他并发助手）；该助手空闲则显示「发送」，点击立即执行——即使其他助手正在跑（2026.09.03 起多助手并发，互不排队）
典型用途「测试不用跑 XX」「换个方案实现」「这个函数干嘛的」「帮我加个注释」
附属功能—权限下拉（自动审批 / 手工审批 / 只读，随助手记忆，缺省自动审批）：自动审批＝工具全开不询问；手工审批＝助手改动工程/执行有影响操作前须先征得你同意——所有后端都会弹窗（Claude Code 走 ask_user；DSH/Pi/Codex/Hermes 助手运行 --ask 弹窗命令，窗口由 AutoCode 主程序弹出，用户作答回传助手；多助手同时提问时自动排队逐个弹）；只读＝仅查询分析禁改工程（Claude/Pi 后端工具硬禁，DSH/Codex/Hermes 由提示词约束，且不拍快照/不沉淀经验）。另有 ↶ 撤销（对话层撤销最后一条提问，连带其回复一并移除；与源码回退正交）、上下文条（绿≤70%/红>70%，点击或右键弹出「立即压缩上下文 / 设置上下文大小」——作用于该助手自己的会话，上下文过大时手动压缩可显著提速降费）；页底统计栏＝[状态图标][费用/输入/输出/请求/耗时][本轮 ↑↓]——状态图标转圈表示该助手运行中，只反映该助手自己的状态

⏪ 代码回退：记录点 + 双粒度恢复

左栏 「回退」按钮打开统一回退界面（需先打开工程、任务非运行中）。工程源码在关键时点自动增量备份为「记录点」：

记录点类型说明
任务阶段边界任务每进入新阶段前留底，可整体回到「设计完成时」「开发前」等任意边界。
助手轮次助手每轮改码前留底，可精确回到某一问一答之前。
回退前快照每次执行回退前自动再留一份当前现场——回退本身也可撤销，放心操作。

界面左侧选记录点，右侧即列出该时点的文件变动明细（新增/修改/删除）；选中后点「回退到此记录点」确认执行（双击记录点不执行回退，防误触）。右侧文件列表支持右键 →「查看变更」（或直接双击文件行）：弹出双栏并排对比窗口（类 Beyond Compare），左侧为上一记录点内容、右侧为当前记录点内容，变化区域自动标红/标绿、公共前后缀对齐、滚动条联动，可直观查看该文件具体改了什么；新增文件左侧显示「不存在」、删除文件右侧显示「不存在」，二进制文件不做文本对比。回退过程中断（断电/崩溃）会在下次打开工程时自动检测并还原到回退前状态，不会留下半截现场。备份为 CAS 增量存储（相同内容只存一份、只备份代码/构建配置/文档文本等代码相关文件，*.obj/*.exe/*.png 等中间产物不入库），占用小、速度快；回退不触碰非代码文件（原地保留）。

提示词栏的「↶ 撤销」是对话撤销（撤回最后一条提问），与此处的源码回退是两回事，互不影响。

🤝 人工介入：时机与注意事项

全自动不等于放任不管。AutoCode 提供四种介入通道，可靠程度各不相同 —— 真正可靠的介入点是「阶段边界」和「熔断升级后」，运行中途的实时插话受底层协议限制基本不生效（见下）。

通道说明可靠程度
① 介入输入栏
（日志页下方）		 任务运行中输入指令（Ctrl+Enter 发送），指令记入对话流。仅当前正在运行的任务可用，其他状态输入栏自动禁用（不会静默丢弃）。
⚠️ 已知限制：阶段子进程启动后输入通道即关闭，中途插话多数情况不会真正送达——指令会被记录（injected 事件）供后续阶段参考，但无法打断正在跑的阶段。要立即纠偏请用 ②。		 ⚠️ 仅记录
② 阶段边界介入 子进程无法真正中途挂起，所以「暂停」= 当前阶段跑完、进入下一阶段前停下（不会产生半截产物）—— 这正是你的介入窗口。
推荐套路：暂停 → 手动修改产物或代码（如直接编辑 requirements.md / design.md）→ 「继续」从下一阶段恢复，或阶段表右键「再次执行」只重跑该阶段（跑完停住，不推进后续）。		 ✅ 最可靠
③ 熔断升级
（系统主动请你）		 两种触发：同一阶段被驳回超过 3 次仍不通过，或上游输入多次生成失败 → 任务自动暂停并提示「已暂停并升级到用户处理」。
处置：打开 .autodev/tasks/<任务id>/escalation.md（含驳回焦点、最近阶段历史与处置建议），三选一：直接改代码后重跑 / 调整任务描述再继续 / 放宽验收要求。		 ✅ 可靠
④ 助手反向提问
（ask_user）		 「助手」页问答时，Claude 若缺关键信息会主动弹窗向你提问——是它来找你，不影响任务流水线。选项列表末尾有「其他（自行输入）」，不在列表里的问题可自由输入。 ✅ 按需回答

场景能否介入方式
阶段运行中实时插话⚠️ 名义能，实际仅记录介入输入栏（已知限制）
阶段边界✅ 能暂停 → 手改产物/代码 → 继续或右键重跑该阶段

🧠 自定义大模型（四后端共享，DSH / PIAgent / CodexHarness / Hermes）

2026.09.10 起四个后端共享同一份模型列表与「当前」模型：在任一后端页新增/编辑/删除/设为当前，其余后端页同步生效，切换后端无需重新配置模型。合并规则 = 四张表（[DshModels]/[PiModels]/[CodexModels]/[HermesModels]）以条目最多的表为基底、其余表的新条目（按请求地址+API格式+模型名同身份去重）追加；共享「当前」取基底表的激活条目。字段 = 显示名、请求地址（网关 URL）、API 格式（anthropic-messages 原生 / chat / responses）、模型名称、API Key、上下文窗口、最大输出。条目编辑不要求把该后端选为当前 Agent 后端（也不要求已安装）——可提前预配，切到该后端时激活条目即生效：AutoCode 在每次阶段启动前幂等自愈写入 ~/.pi/agent/models.json、~/.codex/（config.toml + auth.json）或部署根 config.yaml（Hermes），多实例并发也不会互相覆盖坏。保存时同一份内容写回四张节，启动/选中任务时自动合并归一后统一应用（任务级覆盖、全局超集等既有机制不变）。列表列宽可用鼠标拖动表头分隔线调整（每列含请求地址均可调，双击分隔线自适应内容），调整结果自动记忆在 config.ini [Layout]，下次打开设置页保持；末列「当前」自动拉伸填满剩余宽度。

注意：Codex 只能连 chat completions 兼容端点（openai-completions 等同 chat）；anthropic-messages 端点的条目不能设为 Codex 的当前模型。另外「最大输出」不得超过网关上限 131072（2^17）——超限值会触发网关 500，该后端全部请求失败。PIAgent 页还有「计费单价($/M)」四项（纯输入/缓存读/缓存写/输出），配置后任务费用列自动折算，全 0 则显示 "-"。

常见问题

助手提示「调用失败：无错误文本（subtype=error_during_execution）」？

失败消息会自动附带真因（stderr 尾部 / 会话错误记录）。常见两类：① 「No conversation found with session ID」——正在恢复的会话 id 在本机不存在：工程/助手档自其他电脑拷贝时必现（会话数据存在 ~/.claude，不随工程目录走），2026.08.27 起已自动降级为新建会话重发本轮（日志可见「↻ 会话在本机不存在…」），无需处理；若旧版仍失败，新建一个助手即可。② 认证/网络类（stderr 含 api key/401/login 等）——在该电脑命令行运行一次 claude 交互式完成登录；走网关中转需配置 ANTHROPIC_BASE_URL / ANTHROPIC_AUTH_TOKEN，或换用 DSH/PIAgent/CodexHarness 后端+自定义模型条目。

点「新建任务」提示"请先打开工程目录"？

AutoCode 的所有任务都依附于工程。先通过 工程(P) → 打开工程目录... 打开一个代码目录（或新建工程目录），再创建任务。

任务显示 Paused（暂停），怎么回事？

两种可能：① 你点了「暂停」——阶段边界正常停下，点「继续」从下一阶段恢复；② 同一阶段迭代超过 3 次仍不通过——系统主动暂停并升级，请查看日志页末尾的评审意见，修改需求描述或处理后点「继续」。

首次打开工程很慢 / 状态栏一直显示 guide 生成中？

首次打开会调用 Claude 完整扫描代码库生成 guide.md，大工程需几分钟，属正常现象。仅首次较慢，之后增量更新。若生成失败，菜单「同步 Guide」可重试。

怎么中途修改 Claude 的做法？

任务运行中，可在日志页下方的介入指令框输入要求（如「不要动 ui 目录」「补上单元测试」），Ctrl+Enter 发送，指令会记入对话流供后续阶段参考；但正在运行的阶段无法被打断（已知限制）。要立即纠偏，推荐：点「暂停」（当前阶段跑完即停）→ 手动修改产物/代码 → 「继续」或右键单阶段「再次执行」。详见「人工介入」一节。

任务失败了，代码改了一半怎么办？

三个工具：① 历史任务右键「再次执行」整体重跑；② 阶段表右键「再次执行」只重跑某一阶段；③ 左栏「回退」按钮把工程源码回退到任意记录点（改码前的现场也会自动快照留底）。

切换口径（2026.09.10 起）：选中任务（启动/再次执行/点选任务列表）右侧自动显示该任务的任务日志；「再次执行」同时切回「当前任务」页；任务跑完/失败自动切到「历史任务」页选中该任务，日志保持最终输出；取消选中/移除/删除任务（无选中任务）则右侧切到当前助手日志。

打开工程后任务列表是空的 / 历史任务不见了？

历史任务存在工程的 .autodev/history.db 中，每个任务另有权威档案 .autodev/tasks/<id>/task.json。即使历史库意外损坏（如异常断电），程序打开工程时会自动体检：坏库收档为 history.db.corrupt-日期时间并自动从 task.json 重建，历史记录随即恢复，无需手工处理（收档文件确认无用后可删）。

多个助手 Tab 怎么用？会互相干扰吗？

点助手区的「＋」可开多个助手，每个助手是独立 Agent（独立进程/会话链/上下文），可多个同时运行互不干扰——A 在跑时切到 B 发指令立即执行，不等 A（2026.09.03 起不再排队）。各自独立会话与日志，互不串流。Tab 可拖动排序、双击改名；点 × 关闭的助手会话仍保留，右上角 ▾ 可随时恢复；全部助手页都关掉前至少保留一个。会话随任务档自动保存，重开工程后原样恢复。2026.09.05 起各助手页内自带独立的输入栏与统计栏（切换 Tab 整套切换，草稿与消耗互不干扰；助手消耗只记在助手自己名下，不并入任务统计）。

费用在哪看？会超支吗？

右栏底部实时显示当前任务费用与 token 消耗（任务侧专用；各助手自己的消耗在各自助手页内统计栏，2026.09.05 起与任务统计完全隔离）；任务详情（右键「查看任务内容」）可看单任务累计费用。历史记录存在每个工程自己的 .autodev/history.db 里（随工程目录走、可多实例共用，含 5 秒并发写保护 + WAL）。

能同时跑多个任务吗？

当前版本执行层为单任务串行（保证工程文件不被并发写坏）；新任务可先建好排队，当前任务结束后依次执行。

标题栏的版本号三个数字是什么意思？

三段式 v主.次.编译号（如 v1.0.25）：主版本 = 架构级大改版，次版本 = 功能迭代，编译号 = 每次构建自动 +1，用于精确对应某个 exe。

同时运行多个 AutoCode，配置和工程怎么同步？

同一目录的多个实例（如多次启动 Execute\AutoCode.exe）：共享 exe 同级 config.ini，后端/模型/扫描排除等设置保存后其他实例约 1 秒内自动热同步（状态栏提示「配置已从其他 AutoCode 实例同步」）；2026.09.07 起「最近打开」列表也跨实例实时同步（他实例打开/移除工程，本实例菜单即时刷新）。不同目录的实例（如 Execute 与 Execute - 副本）：两份独立 config.ini，互不同步——需保持后端/模型一致时请手工对齐（注意 ~/.pi/agent/models.json 等为两份配置共同写入的全局文件，配置不一致时后写者生效）。

同一工程不要在两个实例里同时操作：助手对话（assistant.json）、任务状态（task.json）、guide/record 等都是整文件写入，双开同工程会「后写覆盖先写」互相冲掉（仅历史库 history.db 并发安全）。2026.09.07 起有工程在席锁（.autodev/instance.lock，记录持锁实例 PID）：手动打开已被其他实例使用的工程会弹确认警告；程序崩溃残留的锁会按 PID 存活自动失效，不阻断后续打开。启动时不会自动打开任何工程（2026.09.09 起移除自动恢复），多实例可各自从「最近打开」选择不同工程。

DeepSeekHarness / PIAgent / CodexHarness 是什么？必须装吗？

三个都是与 Claude Code 并列的可选 Agent 后端（DSH = DeepSeek 官方框架；PIAgent = pi-coding-agent；CodexHarness = OpenAI Codex CLI 0.87.0）。不装完全不影响——默认走 Claude Code 后端。想用哪个：设置 → 对应参数页 → 安装按钮（详见「可选后端的安装」）→「重新检测」→「Agent 后端」切换（任务运行中禁止切换）。三个后端都支持自定义网关模型条目（设置页「自定义大模型」组）。

PIAgent 报 "Unknown provider autocode-1" 或请求全部失败？

多见于网关配置异常或「最大输出」超限。检查：① 设置页 PIAgent 模型条目的「最大输出」不得超过 131072（网关上限，超限必 500）；② 网关地址（如 192.168.118.128:9000）本机可达；③ 点「重新检测」确认安装有效。AutoCode 已在每次阶段启动前自动重写 ~/.pi/agent/models.json 自愈此类问题，偶发时重跑该阶段即可。

PIAgent 报 429 "inference tpm exhausted"（每分钟 token 配额限流）？

模型服务的分钟级限流（TPM/RPM），非配置错误。AutoCode 已自动把 PIAgent 的自动重试退避拉长为 15/30/60 秒（写入 ~/.pi/agent/settings.json 的 retry 段，可跨过配额滚动窗口），日志中会显示「↻ 模型接口瞬态错误…自动重试」进度；多次重试后仍失败时会明确报错并提示处理办法：稍等 1~2 分钟重发、减小上下文（新开助手）或换配额更高的模型。若频繁触发，说明当前模型/账号的每分钟配额小于单步上下文用量，应换模型。

在工程资源管理器里点 exe 无法运行，系统资源管理器双击却正常？

旧版打开非文本文件时未指定工作目录，exe 继承了 AutoCode 的当前目录而不是自己的文件夹——用相对路径读资源/配置的程序（游戏、便携软件常见）启动即退出，看起来就是「点了没反应」。现版已对齐 Windows 资源管理器双击口径：exe 以自身所在目录为工作目录启动，可直接正常运行；打开失败时会弹窗显示具体错误码。

Codex 后端能统计费用吗？

能。CodexHarness 经本地代理实时捕获每轮 usage（输入/输出 token 与请求数），任务运行中费用/输入/输出/请求四列即时刷新；DSH 与 PIAgent 同样支持（Pi 需在设置页配置计费单价四项后折算金额）。
