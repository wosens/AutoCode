亮点速览

先看最值得知道的六件事

🏭 全流程自动编排 需求收集 → 需求确认 → 评审 → 设计 → 计划 → 开发 → 代码审查 → 测试，每个阶段自动调度 Claude 执行，全程无需人工盯守。

🧠 工程记忆 guide.md 打开工程时自动扫描代码库生成架构总览，后续每次改动追加流水记录并支持一键同步，Claude 越干越懂你的项目。
📦 绿色便携 · 随手可用 单文件夹即整软件，配置随程序走；首次使用「环境安装」一键装齐 Git / Node.js / Claude Code CLI。

30 秒上手

四步跑通第一个任务

装环境（仅首次） — 菜单 功能(F) → 环境安装...，授权后自动安装 Git、Node.js 与 Claude Code CLI。
已装过可跳过；DeepSeekHarness 为可选组件，脚本结束前会询问是否一并安装（不装不影响使用）；脚本位于程序目录 install_env.bat，也可右键以管理员身份手动运行。
打开工程 — 菜单 工程(P) → 打开工程目录... 选择你的代码目录（或「新建工程目录...」从零开始）。
首次打开会自动扫描代码库生成 .autodev/guide.md（工程架构记忆），需几分钟；下次打开自动恢复上次工程。
新建任务 — 左栏 新建 按钮：填任务名称、选类型（Feature / Bugfix）、写需求描述，勾选「立刻启动任务」点确定。
不勾立刻启动，则之后选中任务点「继续」再启动。
看结果 — 右栏阶段表逐个点亮；「日志」页看执行过程，「阶段产物」页看每阶段生成的 .md 文档，完成后工程代码即已修改。
需要纠偏时：任务运行中可在日志页下方「介入指令」框留言；要立即生效则先「暂停」改完再继续（详见「人工介入」一节）。

界面总览

一屏读懂：左管任务，右看执行

区域名称作用
1菜单栏 工程(P) 新建/打开工程、最近打开、同步 Guide；功能(F) 设置、环境安装；帮助(H) 本说明、关于。
2任务列表（当前 / 历史 Tab） 「当前任务」列本工程进行中的任务；「历史任务」列本工程已完成/失败的全部任务（存在工程自己的 .autodev/history.db，随工程走），支持右键「再次执行」。
3任务控制按钮 新建 / 继续 / 暂停 / 停止 / 回退，按钮随所选任务状态自动启用禁用。
4工程资源管理器 以工程目录为根节点浏览工程内全部文件（自动隐藏 .autodev/build/Execute/.git 等生成目录）；双击用系统默认程序打开，右键支持剪切/复制/粘贴/删除/改名/复制路径/「通过资源管理器打开」/「添加到聊天框」等。
5阶段进度表 当前任务的阶段清单与状态（已完成/进行中/等待），右键某阶段可「再次执行」（仅重跑该阶段）。
6日志 / 阶段产物 / 助手 Tab / 文件预览 日志=任务执行对话流；阶段产物=各阶段生成的 .md 文档；助手=可开多个的独立问答助手（动态 Tab）；双击资源管理器文件生成预览页。
7费用 / Token 统计 当前任务累计费用（美元）与输入/输出 token 数。
8状态栏 当前工程路径、guide.md 状态、已载入任务数。

工作流与阶段

AutoCode 的核心：两条流水线 + 三道评审关卡

① Feature 流程（新功能，10 个阶段）

需求收集1→ 确认需求2→ 需求评审3→ 设计4→ 设计评审5→ 计划6→ 计划评审7→ 开发8→ 代码审查9→ 测试10→ ✅ 完成

② Bugfix 流程（修缺陷，8 个阶段）

需求收集1→ 确认需求2→ 根因分析11→ 根因核实12→ 修复13→ 代码审查9→ 测试10→ ✅ 完成
分组： 需求 设计 计划 实现 质检 缺陷专线

③ 评审驳回 → 自动打回重做

④ 任务状态一览

状态含义可执行操作
🟡 Pending已创建未启动继续（启动）
🔵 Running执行中暂停、停止、介入指令
⏸ Paused暂停（含迭代超限自动升级）继续（从下一阶段恢复）
⏹ Stopped被手动终止继续（续跑）、回退
✅ Done全部阶段完成（转入历史）右键「再次执行」
❌ Failed执行失败（转入历史）右键「再次执行」重试
「暂停」是阶段边界暂停：当前阶段会跑完，在进入下一阶段前停下 —— 不会产生半截产物。

功能详解

🛠 工程管理

操作说明
新建工程目录...选一个空目录新建工程，自动初始化 .autodev 并生成 guide.md。
打开工程目录...打开已有代码目录；首次打开自动扫描生成 guide.md（耗时数分钟）。
最近打开最近工程一键直达（子菜单最多 10 条，末尾「...」打开全量历史对话框）；启动时自动恢复上次工程。
同步 Guide按 record.md 中的改动流水增量更新 guide.md（任务完成后也会自动触发，此处为手动入口）。
任务右键菜单当前任务：查看任务内容 / 移除；历史任务：查看任务内容 / 再次执行。
回退按钮打开统一回退界面：左侧记录点列表（任务阶段 / 助手轮次双粒度，增量备份），右侧文件变动明细，双击记录点即可把工程源码回退到该时点。回退前会先把当前现场自动快照留底，随时可再撤销回来。

📂 工程资源管理器

左栏底部的文件树：工程目录本身就是根节点（打开后自动展开），显示工程内全部文件；生成目录（.autodev、build、Execute、.git、node_modules）自动整目录隐藏，保持树面干净。

操作说明
双击文件 / 目录用系统默认程序打开（目录则用资源管理器打开）。
通过资源管理器打开目录直接打开该目录；文件则打开所在目录并定位选中该文件。
剪切 / 复制 / 粘贴工程内文件与目录的移动复制（粘贴有同名冲突提示）。
删除 / 改名删除有二次确认；改名弹输入框，目标已存在会拦截。
复制路径 / 复制相对路径绝对路径 / 相对工程根的路径写入剪贴板（Windows 原生分隔符）。
添加到聊天框把选中文件的路径插入「助手」提问框，向 Claude 提问时直接引用该文件。

📁 工程数据都存在哪？—— .autodev 目录

所有任务产物都落在工程自己的 .autodev/ 目录里，随工程走、可提交进版本库：

<工程根>/ └── .autodev/ ├── guide.md ← 工程架构总览（Claude 的“项目记忆”，自动生成） ├── record.md ← 全局修改流水（每次改动追加） ├── history.db ← 本工程历史任务库（随工程走；损坏自动收档重建） └── tasks/ └── <task-id>/ ← 每个任务一个私有目录，互不干扰 ├── task.json ← 任务档案（进度 / 迭代 / 费用，权威数据源） ├── assistant.json ← 助手会话档（多助手 Tab、撤销栈） ├── backups/ ← 增量备份存储（回退界面的记录点数据） └── intake.md / requirements.md / design.md / plan.md / cr.md / root_cause.md ...

📊 执行面板（右栏）

页签内容
日志任务执行的完整对话流：Claude 的分析文本、每次工具调用（Read/Edit/Bash...）及结果，底部可发「介入指令」中途纠偏（仅任务运行中可用）。
阶段产物按阶段列出 .autodev/tasks/<id>/ 下生成的 .md 文档（需求书、设计书、计划书、审查报告...），右侧直接渲染阅读。
助手 1 / 助手 2 / …动态多助手 Tab，每个 Tab 一条独立问答会话（互不串流）：「＋」页新增助手；Tab 上 × 关闭（会话保留可恢复）；右上角 ▾ 弹出已关闭助手列表选名恢复；拖动排序、双击改名。运行中的助手独立累计日志，切走再看也不丢。
文件预览资源管理器单击文件生成预览页，双击切到该页（多文件并存）。

💬 两个输入框，用途不同

介入指令（日志页下方）助手输入（助手页下方）
对象正在运行的任务独立助手会话
时机仅任务 Running 时可用打开工程后随时可用；助手运行中仍可打字，发送变「➤ 追加指令」（本轮结束后自动发出）或「⏹ 停止」
典型用途「测试不用跑 XX」「换个方案实现」「这个函数干嘛的」「帮我加个注释」
附属功能—只读开关（禁止改文件）、↶ 回退（对话层撤销最后一条提问，连带其回复一并移除；与源码回退正交）、上下文条（绿≤70%/红>70%，右键可手动压缩/设窗口上限）

⏪ 代码回退：记录点 + 双粒度恢复

左栏 「回退」按钮打开统一回退界面（需先打开工程、任务非运行中）。工程源码在关键时点自动增量备份为「记录点」：

记录点类型说明
任务阶段边界任务每进入新阶段前留底，可整体回到「设计完成时」「开发前」等任意边界。
助手轮次助手每轮改码前留底，可精确回到某一问一答之前。
回退前快照每次执行回退前自动再留一份当前现场——回退本身也可撤销，放心操作。

界面左侧选记录点，右侧即列出该时点的文件变动明细（新增/修改/删除）；双击记录点或点「回退到此记录点」确认执行。回退过程中断（断电/崩溃）会在下次打开工程时自动检测并还原到回退前状态，不会留下半截现场。

提示词栏的「↶ 回退」是对话撤销（撤回最后一条提问），与此处的源码回退是两回事，互不影响。

🤝 人工介入：时机与注意事项

全自动不等于放任不管。AutoCode 提供四种介入通道，可靠程度各不相同 —— 真正可靠的介入点是「阶段边界」和「熔断升级后」，运行中途的实时插话受底层协议限制基本不生效（见下）。

通道说明可靠程度
① 介入输入栏
（日志页下方）		 任务运行中输入指令（Ctrl+Enter 发送），指令记入对话流。仅当前正在运行的任务可用，其他状态输入栏自动禁用（不会静默丢弃）。
⚠️ 已知限制：阶段子进程启动后输入通道即关闭，中途插话多数情况不会真正送达——指令会被记录（injected 事件）供后续阶段参考，但无法打断正在跑的阶段。要立即纠偏请用 ②。		 ⚠️ 仅记录
② 阶段边界介入 子进程无法真正中途挂起，所以「暂停」= 当前阶段跑完、进入下一阶段前停下（不会产生半截产物）—— 这正是你的介入窗口。
推荐套路：暂停 → 手动修改产物或代码（如直接编辑 requirements.md / design.md）→ 「继续」从下一阶段恢复，或阶段表右键「再次执行」只重跑该阶段（跑完停住，不推进后续）。		 ✅ 最可靠
③ 熔断升级
（系统主动请你）		 两种触发：同一阶段被驳回超过 3 次仍不通过，或上游输入多次生成失败 → 任务自动暂停并提示「已暂停并升级到用户处理」。
处置：打开 .autodev/tasks/<任务id>/escalation.md（含驳回焦点、最近阶段历史与处置建议），三选一：直接改代码后重跑 / 调整任务描述再继续 / 放宽验收要求。		 ✅ 可靠
④ 助手反向提问
（ask_user）		 「助手」页问答时，Claude 若缺关键信息会主动弹窗向你提问——是它来找你，不影响任务流水线。选项列表末尾有「其他（自行输入）」，不在列表里的问题可自由输入。 ✅ 按需回答

介入能力速查

场景能否介入方式
阶段运行中实时插话⚠️ 名义能，实际仅记录介入输入栏（已知限制）
阶段边界✅ 能暂停 → 手改产物/代码 → 继续或右键重跑该阶段
熔断升级后✅ 能（就是请你来）看 escalation.md → 三选一处置后恢复
任务非 Running 状态❌ 不能介入栏已禁用（指令不丢失、不静默忽略）
非当前任务❌ 不能执行层单任务串行，注入只认当前任务
人工审批闸门（如设计须确认后才继续）❌ 尚未实现已列入后续规划
一句话记住：想纠偏，先暂停。暂停永远停在阶段边界，改完东西再继续或单阶段重跑，比指望运行中插话靠谱得多。

⚙️ 设置与环境安装

设置 — 菜单 功能(F) → 设置...：分两页 Tab 集中编辑全部可调参数——「常用」页（运行策略、Agent、评审与助手、目录排除），「DeepSeekHarness参数设置」页（安装状态、node 路径 / DSH 根目录与 provider / 模型）。保存到 exe 同级 config.ini，确定后立即生效——软件保持绿色便携，配置随程序走。

环境安装 — 菜单 功能(F) → 环境安装...：以管理员权限自动安装 Claude Code 运行所需环境 —— Git、Node.js、Claude Code CLI；结束前会询问是否一并安装 DeepSeekHarness（可选的 DeepSeek 官方 Agent 后端）。装一次即可，之后可重复运行修复环境。

DeepSeekHarness（可选后端） — 不装不影响 Claude Code 后端使用。两种装法：

途径说明
环境安装脚本运行 install_env.bat（菜单「环境安装」或右键以管理员身份运行），结束前选 Y 一并安装。
设置页一键安装设置 → 「DeepSeekHarness参数设置」页 → 「安装 DeepSeekHarness…」按钮：以管理员权限运行脚本的单独安装模式（/dsh）。

安装到程序目录内的 DeepSeekHarness\deepseek-harness 子目录（克隆 GitHub 仓库 + pnpm 依赖构建 + 部署 AutoCode 组合文件，需联网数分钟）——随程序目录整体拷走即随身携带，保持绿色便携。装完即用，零手填：AutoCode 启动时自动探测该目录并把根目录回填到 config.ini；设置页也可点「重新检测」立即生效。未安装时设置页的 DeepSeekHarness 参数整体置灰、「Agent 后端」下拉中的该项同时禁用，检测通过后自动解锁。

常见问题

点「新建任务」提示"请先打开工程目录"？

AutoCode 的所有任务都依附于工程。先通过 工程(P) → 打开工程目录... 打开一个代码目录（或新建工程目录），再创建任务。

任务显示 Paused（暂停），怎么回事？

两种可能：① 你点了「暂停」——阶段边界正常停下，点「继续」从下一阶段恢复；② 同一阶段迭代超过 3 次仍不通过——系统主动暂停并升级，请查看日志页末尾的评审意见，修改需求描述或处理后点「继续」。

首次打开工程很慢 / 状态栏一直显示 guide 生成中？

首次打开会调用 Claude 完整扫描代码库生成 guide.md，大工程需几分钟，属正常现象。仅首次较慢，之后增量更新。若生成失败，菜单「同步 Guide」可重试。

怎么中途修改 Claude 的做法？

任务运行中，可在日志页下方的介入指令框输入要求（如「不要动 ui 目录」「补上单元测试」），Ctrl+Enter 发送，指令会记入对话流供后续阶段参考；但正在运行的阶段无法被打断（已知限制）。要立即纠偏，推荐：点「暂停」（当前阶段跑完即停）→ 手动修改产物/代码 → 「继续」或右键单阶段「再次执行」。详见「人工介入」一节。

任务失败了，代码改了一半怎么办？

三个工具：① 历史任务右键「再次执行」整体重跑；② 阶段表右键「再次执行」只重跑某一阶段；③ 左栏「回退」按钮把工程源码回退到任意记录点（改码前的现场也会自动快照留底）。

打开工程后任务列表是空的 / 历史任务不见了？

历史任务存在工程的 .autodev/history.db 中，每个任务另有权威档案 .autodev/tasks/<id>/task.json。即使历史库意外损坏（如异常断电），程序打开工程时会自动体检：坏库收档为 history.db.corrupt-日期时间并自动从 task.json 重建，历史记录随即恢复，无需手工处理（收档文件确认无用后可删）。

多个助手 Tab 怎么用？会互相干扰吗？

点助手区的「＋」可开多个助手，各自独立会话与日志，互不串流（一个在跑时切到另一个提问也不冲突）。Tab 可拖动排序、双击改名；点 × 关闭的助手会话仍保留，右上角 ▾ 可随时恢复；全部助手页都关掉前至少保留一个。会话随任务档自动保存，重开工程后原样恢复。

费用在哪看？会超支吗？

右栏底部实时显示当前任务费用与 token 消耗；任务详情（右键「查看任务内容」）可看单任务累计费用。历史记录存在每个工程自己的 .autodev/history.db 里（随工程目录走、可多实例共用，含 5 秒并发写保护 + WAL）。

能同时跑多个任务吗？

当前版本执行层为单任务串行（保证工程文件不被并发写坏）；新任务可先建好排队，当前任务结束后依次执行。

标题栏的版本号三个数字是什么意思？

三段式 v主.次.编译号（如 v1.0.25）：主版本 = 架构级大改版，次版本 = 功能迭代，编译号 = 每次构建自动 +1，用于精确对应某个 exe。

DeepSeekHarness 是什么？必须装吗？

DeepSeek 官方开源的 Agent 执行框架，是 AutoCode 里与 Claude Code 并列的可选 Agent 后端（JSON-RPC 完整接入，支持流式过程与 token 统计）。不装完全不影响——默认走 Claude Code 后端。想用的话：设置 → 「DeepSeekHarness参数设置」页 → 「安装 DeepSeekHarness…」一键安装（或环境安装脚本结束前选 Y）；装完点「重新检测」，根目录自动填入，再把「Agent 后端」切到 DeepSeekHarness 即可（任务运行中禁止切换）。
