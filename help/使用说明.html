亮点速览

先看最值得知道的六件事

🏭 全流程自动编排 需求收集 → 需求确认 → 评审 → 设计 → 计划 → 开发 → 代码审查 → 测试，每个阶段自动调度大模型 Agent 执行（Claude Code / DSH / PIAgent / CodexHarness / Hermes 五后端任选），全程无需人工盯守。
🔀 五大 Agent 后端随心切 Claude Code / DeepSeekHarness(DSH) / PIAgent / CodexHarness / Hermes 五后端并列，设置页一键切换；DSH/Pi/Codex/Hermes 四后端共享同一份自定义网关模型条目与费用折算（Claude Code 走自身登录）。助手粘性后端：已使用过的助手继续用它自己的 Harness（全局切换不影响它），只有新建助手才用新后端。
🔀 双工作流：Feature / Bugfix 新功能走「设计-计划-开发」主线；修缺陷走「根因分析-核实-修复」专线，互不拖累，各走各的最短路径。
🔄 评审驳回自动迭代 内置三道评审关卡，不通过自动打回上游阶段重做；每阶段最多重跑 3 次，超过则弹人工介入窗——可人工确认放行继续、再迭代一轮或保持暂停，绝不无限空转。
📊 过程全透明 阶段图标条实时点亮推进；日志页完整呈现 Agent 的每句话、每次工具调用；底部实时统计费用与 token 消耗，花销一目了然（未选中任务时该栏自动隐藏，纵向空间还给日志）。
🧠 工程记忆 guide.md 打开工程时自动扫描代码库生成架构总览，后续每次改动追加流水记录并支持一键同步，Agent 越干越懂你的项目。
📦 绿色便携 · 随手可用 单文件夹即整软件，配置随程序走；首次使用「环境安装」一键装齐 Git / Node.js / Claude Code CLI。

30 秒上手

四步跑通第一个任务

装环境（仅首次） — 菜单 功能(F) → 环境安装...，授权后自动安装 Git、Node.js 与 Claude Code CLI。
已装过可跳过；DeepSeekHarness 为可选组件，脚本结束前会询问是否一并安装（不装不影响使用）；脚本位于程序目录 install_env.bat，也可右键以管理员身份手动运行。
打开工程 — 菜单 工程(P) → 打开工程目录... 选择你的代码目录（在对话框中新建一个空目录即可从零开始）。
首次打开会自动扫描代码库生成 .autodev/guide.md（工程架构记忆），需几分钟；下次可从「最近打开」子菜单一键回到常用工程（启动时不自动加载）；启动页顶部有搜索框（2026.10.11 起）——输入即时过滤工程按钮（按名称/路径匹配，不区分大小写），状态栏实时显示「匹配 M / N 个工程」，清空恢复全部；「跳过」按钮（2026.10.14 起）——不选工程直接进入主界面，自动在程序目录下创建 AutoCode 文件夹并作为工作目录，可正常创建任务、与助手对话（不算工程，不进「最近打开」列表，标题栏仍显示 AutoCode 版本）。
新建任务 — 左栏 新建 按钮：填任务名称、选类型（Feature / Bugfix）、写需求描述，勾选「立刻启动任务」点确定。
不勾立刻启动，则之后选中任务点「继续」再启动。
看结果 — 右栏阶段图标条逐个点亮；「日志」页看执行过程，「阶段产物」页看每阶段生成的 .md 文档，完成后工程代码即已修改。
需要纠偏时：任务运行中可在日志页下方「介入指令」框留言；要立即生效则先「暂停」改完再继续（详见「人工介入」一节）。

界面总览

一屏读懂：左管任务，右看执行

区域名称作用

2任务列表（当前 / 历史 Tab） 「当前任务」列本工程进行中的任务；「历史任务」列本工程已完成/失败的全部任务（存在工程自己的 .autodev/history.db，随工程走），支持右键「再次执行」。

4工程资源管理器 以工程目录为根节点浏览工程内全部文件（自动隐藏 build/.git/.vs/node_modules 等生成目录，隐藏清单可在设置页「资源管理器隐藏目录」调整；.autodev 与 Execute 可见）；单击文件即预览（文本类进内嵌预览页但不切页），双击文本类切到预览页，exe 等非文本文件以文件所在目录为工作目录调系统默认程序运行（与 Windows 资源管理器双击一致，游戏/便携程序可正常启动），支持 Windows 式拖拽（拖出到资源管理器/聊天窗口、树内移动/复制、拖入导入），右键支持剪切/复制/粘贴/新建文件夹（目标=选中目录/选中文件所在目录/工程根；建完即定位并进入行内命名，重名自动编号）/删除/改名/复制路径/「通过资源管理器打开」/「打开方式」/「添加到聊天框」/「属性」（2026.10.02）/「刷新」等。「属性」：调 Windows 资源管理器原生属性框（常规/安全/详细信息等同源多页签，文件与文件夹均支持）；系统接口不可用时自动弹内置属性窗（名称/类型/位置/大小（文件夹递归统计）/修改与创建时间，只读、隐藏勾选可写回）。「打开方式」子菜单与 Windows 资源管理器同源（系统 Shell 枚举，含 VS/VSCode/Qoder/Trae/记事本/写字板等用户级注册的全部程序，显示名同系统本地化名称；点击由系统启动——自动处理参数展开与 DDE 类动词，Visual Studio 等可正常打开文件）。批处理文件（.bat/.cmd）精简口径（2026.09.26）：首项固定「用 CMD 运行」（cmd /k 执行该批处理，完成后保留窗口显示输出），其后仅列推荐编辑器，不再堆全量程序列表（普通扩展名不受影响，兜底列表封顶 12 项）。可执行文件（.exe/.msi/.com/.scr/.pif）同口径收敛（2026.10.09）：仅列推荐程序，无推荐时子菜单禁用（与资源管理器对可执行文件的语义一致，不再倒出全机自荐程序）。右键菜单全部菜单项均带图标（固定项为内置矢量图标，「打开方式」各项显示对应程序的真实图标）。任务列表右键（查看任务内容/重命名/自动命名/再次执行/移除等）、阶段条右键、上下文进度条菜单、助手 Tab 右键「彻底删除」、回退窗口文件列表「查看变更」等其余右键菜单同样带图标。
5阶段图标条 当前任务的阶段横向图标条（2026.09.04 起，替代旧的纵向阶段表）：每阶段一个圆形状态图标 + 短名，连接线指示推进进度——✔绿=已完成、▶蓝=进行中、✖红=失败、⏸黄=未完成、○灰=待执行；鼠标悬停显示阶段全名与状态，右键某阶段可「再次执行」（仅重跑该阶段）。整条固定一行高，纵向空间全部留给日志区。
6日志 / 阶段产物 / 助手 Tab / 文件预览 日志=任务执行对话流；阶段产物=各阶段生成的 .md 文档；助手=可开多个的独立问答助手（动态 Tab）；双击资源管理器文件生成预览页。
7费用 / Token 统计 当前任务累计费用（美元）与输入/输出 token 数。仅任务侧（2026.09.05 起任务与助手统计完全隔离），紧跟在状态图标之后（图标转圈=任务运行中、空闲色点=任务状态）；各助手自己的费用/token/请求/耗时统计在各自助手页内统计栏，同样自带状态图标（转圈=该助手运行中）。
8状态栏 当前工程路径、guide.md 状态、已载入任务数。

工作流与阶段

AutoCode 的核心：两条流水线 + 三道评审关卡

① Feature 流程（新功能，10 个阶段）

需求收集1→ 确认需求2→ 需求评审3→ 设计4→ 设计评审5→ 计划6→ 计划评审7→ 开发8→ 代码审查9→ 测试10→ ✅ 完成

② Bugfix 流程（修缺陷，8 个阶段）

需求收集1→ 确认需求2→ 根因分析11→ 根因核实12→ 修复13→ 代码审查9→ 测试10→ ✅ 完成
分组： 需求 设计 计划 实现 质检 缺陷专线

③ 评审驳回 → 自动打回重做

评审人工介入（2026.09.22 新增）：评审阶段多次驳回达到迭代上限时，不再静默暂停——弹出「评审人工介入」窗（11pt 字体，Esc/回车缺省＝保持暂停）：「人工放行，继续」视为评审通过直接推进后续流程（评审报告仍随产物保留备查）；「再迭代一轮」重置迭代计数并重跑回炉阶段（评审意见仍会注入提示词）；「保持暂停」维持升级暂停语义，稍后在任务列表点「继续」自行处理。无人值守跑批可在 config.ini 配 [Policy] ReviewAskOnEscalate=0 关闭弹窗（退回旧静默升级）。

④ 任务状态一览

状态含义可执行操作
🟡 Pending已创建未启动继续（启动）
🔵 Running执行中暂停、停止、介入指令
⏸ Paused暂停（含迭代超限自动升级）继续（从下一阶段恢复）
⏹ Stopped被手动终止继续（续跑）、回退
✅ Done全部阶段完成（转入历史）右键「再次执行」
❌ Failed执行失败（转入历史）右键「再次执行」重试
「暂停」是阶段边界暂停：当前阶段会跑完，在进入下一阶段前停下 —— 不会产生半截产物。

⑤ 代码审查阶段的双重把关（2026-09-30 新增）

任务进入代码审查阶段时，AutoCode 会先对开发阶段落盘的变更清单（changed_files.md）逐文件做一轮静态预审（CodeReview 工程的 ReviewSdk 引擎 + 当前后端大模型），再带预审结论启动 Agent 评审——Agent 需逐条核实预审发现：属实的纳入问题列表并影响通过/驳回决策，误报的说明排除理由。预审结论同时落盘到任务目录 sdk_review.md 供事后查阅（Markdown 报告，含级别/文件/行号/规则/问题/建议）。相关约束：

项说明
开关 [Review] SdkOnStage缺省 1（开启）；置 0 回到纯 Agent 评审（右键手动审查不受影响）。
单轮文件上限 [Review] SdkMaxFiles缺省 12（合法 1..50）：大改动任务截断送审，防预审耗时失控；日志会提示截断。
单文件超时 [Review] SdkTimeoutSec缺省 600 秒（合法 60..3600）。
复用判定同任务同迭代且变更清单未变时不重复预审；驳回打回重改后（迭代号/清单变化）自动重审新代码。预审进行中停止任务会立即终断并落 Stopped，不等预审跑完。
引擎缺失程序目录无 ReviewSdk.dll 时预审自动跳过（日志一次性提示原因），不影响任务正常推进——预审是增强输入而非门禁。

功能详解

🛠 工程管理

操作说明
打开工程目录...打开已有代码目录，也可在对话框中选/建一个空目录从零新建工程（自动初始化 .autodev 并生成 guide.md）；首次打开自动扫描生成 guide.md（耗时数分钟）。
最近打开鼠标悬停即弹出按钮面板（位置与原级联子菜单一致；移到其他菜单项自动隐藏，点击工程按钮才收起）：所有最近工程以小按钮流式排布——每行个数按按钮宽度自适应（宽度上限=面板宽一半），行占满整宽、标题完整显示；约 9 行可视（40~50 个工程），滚轮滚动查看其余；首位「更多...」打开全量历史对话框（顶部搜索框实时过滤、多选右键删除、窗口位置大小记忆）。按钮底色随打开次数渐变：1~5 次基色不变，之后渐红，100 次纯红 (255,0,0)，再渐暗到 255 次暗红 (100,0,0)——一眼看出使用/修改频率（每次成功打开工程累加 1；次数见悬停提示）。悬停按钮：底色变蓝、文字加粗，底部状态栏显示该工程完整路径。启动时不自动加载工程，停留在空工程态由用户手动选择。
同步 Guide按 record.md 中的改动流水增量更新 guide.md（任务完成后也会自动触发，此处为手动入口）。
任务右键菜单当前任务：查看任务内容 / 移除；历史任务：查看任务内容 / 再次执行。
回退按钮打开统一回退界面：左侧记录点列表（任务阶段 / 助手轮次双粒度，增量备份），右侧文件变动明细，选中记录点后点「回退到此记录点」把工程源码回退到该时点（双击不执行回退，防误触）。回退前会先把当前现场自动快照留底，随时可再撤销回来。

📂 工程资源管理器

剪切 / 复制 / 粘贴与 Windows 联动：右键剪切/复制会把文件（支持多选）写入系统剪贴板——直接到 Windows 资源管理器里按 Ctrl+V 即可粘贴（剪切=移动、复制=复制）；反过来在资源管理器里复制/剪切的文件，在本树右键「粘贴」即可粘入当前选中目录（源可以在工程外）。同名目标自动 “ (n)” 编号，跨盘移动自动退化为复制+删源，目录不会移进自己的子目录。剪切粘贴完成后剪贴板自动清空（与资源管理器一致的一次性语义）。

左栏底部的文件树：工程目录本身就是根节点（打开后自动展开），显示工程内全部文件；生成目录（build、.git、.vs、node_modules）自动整目录隐藏，保持树面干净；.autodev（任务产物/记录）与 Execute（部署产物/配置/提示词）可见可浏览。显示隐藏与备份排除互不相干：备份范围由设置页「备份排除目录」（[Backup] ExcludeDirs，默认含 build/Execute/.autodev/node_modules 等——依赖目录文件量巨大且可再生，不备份可把大工程首轮快照从几十分钟降到秒级）单独控制，与树中是否可见无关。隐藏清单可配置（2026.09.23 新增）：设置页「目录排除」组新增「资源管理器隐藏目录」（[Explorer] HiddenDirs，逗号分隔）——预填当前生效清单，想看 build 就把 build 从清单里删掉保存（立即生效，已加载的树同步重显）；清空 = 全部可见。

多根节点与关联项目（2026.09.21 新增）：文件树下方有三个按钮——「添加根节点」弹出目录选择对话框（缺省打开当前工程目录），选中一个关联项目目录后它会作为新的根节点与工程根并排显示（例如主工程 + 它引用的库工程）；「根节点上移 / 下移」调整选中根节点在树顶层的显示顺序。根列表（含顺序）自动持久化到工程的 .autodev/explorer.json，随工程走，重开工程后自动还原；不同工程的关联根集合互不干扰。右键额外根节点可「移除该根节点」（仅移出树，不动磁盘目录；工程根本身不可移除）；与现有根存在嵌套包含关系的目录不能重复添加（嵌套目录本就在父根树内可见）。

展开态自愈（2026.09.22 新增）：Agent 任务运行期间频繁写盘，目录可能被外部增删/重建/重命名——展开的文件夹会随行重建而收起。资源管理器现在会记住本次会话内展开过的目录路径，任何结构变化（包括被删后重建）后行一重新出现就自动恢复展开；用户主动收起的目录不会被强行重新展开。切换工程时记忆自动作废，不跨工程携带。

操作说明
双击文件 / 目录用系统默认程序打开（目录则用资源管理器打开）。
拖拽（2026.08.27 新增）与 Windows 资源管理器一致：拖出——把文件/目录（支持多选）拖到系统资源管理器即复制/移动，拖到聊天软件发送框即作为附件；树内拖动——拖到另一目录默认移动（按住 Ctrl=复制）；拖入——从系统资源管理器拖文件到树上即复制进目标目录。目标同名自动加 “(2)” 序号，目录不可拖入自身子树。

2026.09.10 起各后端共享同一份模型列表与「当前」模型；2026-10-08 起统一在设置 → 「模型」页维护（四后端参数页不再有模型列表；Claude Code 可经页内开关跟随本表，仅 Anthropic 兼容端点条目生效，每轮以环境变量注入接入点/密钥/模型）：新增/编辑/删除/设为当前，切换后端无需重新配置模型；双击单元格就地编辑（2026.10.15）——显示名/接入点/API 类型（下拉）/模型名称/上下文/最大输出六列双击即改（F2 亦可），显示名留空自动回退模型名称、模型名称不可为空、数字列非法输入自动还原；「当前」标记列与完整表单（含密钥）走「编辑…」按钮。合并规则 = 四张表（[DshModels]/[PiModels]/[CodexModels]/[HermesModels]）以条目最多的表为基底、其余表的新条目（按请求地址+API格式+模型名同身份去重）追加；共享「当前」取基底表的激活条目。字段 = 显示名、请求地址（网关 URL）、API 格式（anthropic-messages 原生 / chat / responses）、模型名称、API Key、上下文窗口、最大输出。条目「上下文窗口」为该模型的权威窗口（2026-10-15 起）：助手上下文进度条分母、自动压缩阈值与提示词闸门均按它计算（同名多条目时按实际使用的条目取值——回报模型带槽位前缀的按槽位条目、裸模型名按当前条目）；仅当模型不在表内才回退内置名字探测（GLM=128K / Claude=200K / 未知 200K）。条目编辑不要求把该后端选为当前 Agent 后端（也不要求已安装）——可提前预配，切到该后端时激活条目即生效：AutoCode 在每次阶段启动前幂等自愈写入 ~/.pi/agent/models.json、~/.codex/（config.toml + auth.json）或部署根 config.yaml（Hermes），多实例并发也不会互相覆盖坏。保存时同一份内容写回四张节，启动/选中任务时自动合并归一后统一应用（任务级覆盖、全局超集等既有机制不变）。列表高度随窗口高度自适应（拉高设置窗口即看到更多条目，2026-10-08 起）；列表列宽可用鼠标拖动表头分隔线调整（每列含请求地址均可调，双击分隔线自适应内容），调整结果自动记忆在 config.ini [Layout]，下次打开设置页保持；末列「当前」自动拉伸填满剩余宽度。2026-10-05 快捷切换 ／ 2026-10-07 起仅本助手生效：各助手输入栏右侧的上下文占用条本体直接显示当前模型名（本助手覆盖优先，其次实际回报，未跑过一轮显示共享表当前条目；Claude Code 后端模型自报）；右键菜单「选择模型（仅本助手）」子菜单列出共享表全部条目（勾选＝该助手生效模型；Claude 后端同样可选，标注「需 Anthropic 兼容端点」），点选即为该助手设置对话级模型覆盖——下一轮对话立刻用新模型，不改缺省（全局）模型配置，其他助手与后续新助手仍用全局当前模型；已设覆盖时菜单首项「跟随全局设置…」一键恢复（Claude 后端恢复后按「跟随本表」开关决定走本表或自身配置）。覆盖随助手档案（assistant.json）持久化。全局切换仍走设置 → 模型页「设为当前」。

注意：Codex 只能连 chat completions 兼容端点（openai-completions 等同 chat）；anthropic-messages 端点的条目不能设为 Codex 的当前模型。另外「最大输出」不得超过网关上限 131072（2^17）——超限值会触发网关 500，该后端全部请求失败。PIAgent 页还有「计费单价($/M)」四项（纯输入/缓存读/缓存写/输出），配置后任务费用列自动折算，全 0 则显示 "-"。

常见问题

助手提示「调用失败：无错误文本（subtype=error_during_execution）」？

失败消息会自动附带真因（stderr 尾部 / 会话错误记录）。常见两类：① 「No conversation found with session ID」——正在恢复的会话 id 在本机不存在：工程/助手档自其他电脑拷贝时必现（会话数据存在 ~/.claude，不随工程目录走），2026.08.27 起已自动降级为新建会话重发本轮（日志可见「↻ 会话在本机不存在…」），无需处理；若旧版仍失败，新建一个助手即可。② 认证/网络类（stderr 含 api key/401/login 等）——在该电脑命令行运行一次 claude 交互式完成登录；走网关中转需配置 ANTHROPIC_BASE_URL / ANTHROPIC_AUTH_TOKEN，或换用 DSH/PIAgent/CodexHarness 后端+自定义模型条目。

点「新建任务」提示"请先打开工程目录"？

AutoCode 的所有任务都依附于工程。先通过 工程(P) → 打开工程目录... 打开一个代码目录（新建空目录亦可从零建工程），再创建任务。

任务显示 Paused（暂停），怎么回事？

两种可能：① 你点了「暂停」——阶段边界正常停下，点「继续」从下一阶段恢复；② 同一阶段迭代超过 3 次仍不通过——系统主动暂停并升级，请查看日志页末尾的评审意见，修改需求描述或处理后点「继续」。

首次打开工程很慢 / 状态栏一直显示 guide 生成中？

首次打开会调用 Claude 完整扫描代码库生成 guide.md，大工程需几分钟，属正常现象。仅首次较慢，之后增量更新。若生成失败，菜单「同步 Guide」可重试。

怎么中途修改 Claude 的做法？

任务运行中，可在日志页下方的介入指令框输入要求（如「不要动 ui 目录」「补上单元测试」），Ctrl+Enter 发送，指令会记入对话流供后续阶段参考；但正在运行的阶段无法被打断（已知限制）。要立即纠偏，推荐：点「暂停」（当前阶段跑完即停）→ 手动修改产物/代码 → 「继续」或右键单阶段「再次执行」。详见「人工介入」一节。

任务失败了，代码改了一半怎么办？

三个工具：① 历史任务右键「再次执行」整体重跑；② 阶段表右键「再次执行」只重跑某一阶段；③ 左栏「回退」按钮把工程源码回退到任意记录点（改码前的现场也会自动快照留底）。

切换口径（2026.09.10 起）：选中任务（启动/再次执行/点选任务列表）右侧自动显示该任务的任务日志；「再次执行」同时切回「当前任务」页；任务跑完/失败自动切到「历史任务」页选中该任务，日志保持最终输出；取消选中/移除/删除任务（无选中任务）则右侧切到当前助手日志。

助手运行中切换任务不会停跑助手（2026.09.23 改进）：任何助手正在运行时点击其他任务（或取消选中、启动任务），任务日志/配置立即切换，正在运行的助手不受影响继续干活（运行痕迹继续写入原任务档）；等全部助手结束后，助手面板自动切换到目标任务档。此前口径：点任务会硬停在跑助手。

打开工程后任务列表是空的 / 历史任务不见了？

历史任务存在工程的 .autodev/history.db 中，每个任务另有权威档案 .autodev/tasks/<id>/task.json。即使历史库意外损坏（如异常断电），程序打开工程时会自动体检：坏库收档为 history.db.corrupt-日期时间并自动从 task.json 重建，历史记录随即恢复，无需手工处理（收档文件确认无用后可删）。

多个助手 Tab 怎么用？会互相干扰吗？

点助手区的「＋」可开多个助手，每个助手是独立 Agent（独立进程/会话链/上下文），可多个同时运行互不干扰——A 在跑时切到 B 发指令立即执行，不等 A（2026.09.03 起不再排队）。各自独立会话与日志，互不串流。Tab 可拖动排序、双击改名（右键菜单另有「重命名 / 自动重命名」——自动重命名按该助手全部历史提示词请大模型总结出名称与说明，说明悬停 Tab 可见；2026.10.08 起未改过名的助手首次发送提示词时，先按该提示词自动改名、改完再执行指令）；点 × 关闭的助手会话仍保留，右上角 ▾ 可随时恢复；全部助手页都关掉前至少保留一个。会话随任务档自动保存，重开工程后原样恢复。2026.09.05 起各助手页内自带独立的输入栏与统计栏（切换 Tab 整套切换，草稿与消耗互不干扰；助手消耗只记在助手自己名下，不并入任务统计）。

费用在哪看？会超支吗？

右栏底部实时显示当前任务费用与 token 消耗（任务侧专用；各助手自己的消耗在各自助手页内统计栏，2026.09.05 起与任务统计完全隔离）；任务详情（右键「查看任务内容」）可看单任务累计费用。历史记录存在每个工程自己的 .autodev/history.db 里（随工程目录走、可多实例共用，含 5 秒并发写保护 + WAL）。

能同时跑多个任务吗？

当前版本执行层为单任务串行（保证工程文件不被并发写坏）；新任务可先建好排队，当前任务结束后依次执行。

标题栏的版本号三个数字是什么意思？

三段式 v主.次.编译号（如 v1.0.25）：主版本 = 架构级大改版，次版本 = 功能迭代，编译号 = 每次构建自动 +1，用于精确对应某个 exe。

同时运行多个 AutoCode，配置和工程怎么同步？

同一目录的多个实例（如多次启动 Execute\AutoCode.exe）：共享 exe 同级 config.ini，后端/模型/扫描排除等设置保存后其他实例约 1 秒内自动热同步（状态栏提示「配置已从其他 AutoCode 实例同步」）；2026.09.07 起「最近打开」列表也跨实例实时同步（他实例打开/移除工程，本实例菜单即时刷新）。不同目录的实例（如 Execute 与 Execute - 副本）：两份独立 config.ini，互不同步——需保持后端/模型一致时请手工对齐（注意 ~/.pi/agent/models.json 等为两份配置共同写入的全局文件，配置不一致时后写者生效）。

同一工程不要在两个实例里同时操作：助手对话（assistant.json）、任务状态（task.json）、guide/record 等都是整文件写入，双开同工程会「后写覆盖先写」互相冲掉（仅历史库 history.db 并发安全）。2026.09.07 起有工程在席锁（.autodev/instance.lock，记录持锁实例 PID）：手动打开已被其他实例使用的工程会弹确认警告；程序崩溃残留的锁会按 PID 存活自动失效，不阻断后续打开。启动时不会自动打开任何工程（2026.09.09 起移除自动恢复），多实例可各自从「最近打开」选择不同工程。

DeepSeekHarness / PIAgent / CodexHarness 是什么？必须装吗？

三个都是与 Claude Code 并列的可选 Agent 后端（DSH = DeepSeek 官方框架；PIAgent = pi-coding-agent；CodexHarness = OpenAI Codex CLI 0.87.0）。不装完全不影响——默认走 Claude Code 后端。想用哪个：设置 → 对应参数页 → 安装按钮（详见「可选后端的安装」）→「重新检测」→「Agent 后端」切换（助手运行中可切；任务/guide 运行中暂保留原值）。三个后端都支持自定义网关模型条目（设置页「自定义大模型」组）。

PIAgent 报 "Unknown provider autocode-1" 或请求全部失败？

多见于网关配置异常或「最大输出」超限。检查：① 设置页 PIAgent 模型条目的「最大输出」不得超过 131072（网关上限，超限必 500）；② 网关地址（如 192.168.118.128:9000）本机可达；③ 点「重新检测」确认安装有效。AutoCode 已在每次阶段启动前自动重写 ~/.pi/agent/models.json 自愈此类问题，偶发时重跑该阶段即可。

PIAgent 报 429 "inference tpm exhausted"（每分钟 token 配额限流）？

模型服务的分钟级限流（TPM/RPM），非配置错误。AutoCode 已自动把 PIAgent 的自动重试退避拉长为 15/30/60 秒（写入 ~/.pi/agent/settings.json 的 retry 段，可跨过配额滚动窗口），日志中会显示「↻ 模型接口瞬态错误…自动重试」进度；多次重试后仍失败时会明确报错并提示处理办法：稍等 1~2 分钟重发、减小上下文（新开助手）或换配额更高的模型。若频繁触发，说明当前模型/账号的每分钟配额小于单步上下文用量，应换模型。

在工程资源管理器里点 exe 无法运行，系统资源管理器双击却正常？

旧版打开非文本文件时未指定工作目录，exe 继承了 AutoCode 的当前目录而不是自己的文件夹——用相对路径读资源/配置的程序（游戏、便携软件常见）启动即退出，看起来就是「点了没反应」。现版已对齐 Windows 资源管理器双击口径：exe 以自身所在目录为工作目录启动，可直接正常运行；打开失败时会弹窗显示具体错误码。

Codex 后端能统计费用吗？

能。CodexHarness 经本地代理实时捕获每轮 usage（输入/输出 token 与请求数），任务运行中费用/输入/输出/请求四列即时刷新；DSH、PIAgent 与 Hermes 同样支持（Pi 需在设置页配置计费单价四项后折算金额）。

关闭窗口时提示「当前有正在进行的工作」？

任务或助手运行中关闭主窗口会弹出确认框，逐项列出正在进行的工作（任务名与阶段、运行中的助手、改码前备份），默认选择「取消」防止误关。选择「退出」会中断这些工作——中断的任务可稍后从任务列表「再次执行」继续，助手对话已实时落盘不受影响。

什么是「专家模式深度链」？查询类请求会走吗？

设置 → 评审与助手 → 「启用专家助手」开启后，改码类提示词自动执行深度链：规划 Agent 先制定实施计划与验收标准 → 执行轮照计划实施 → 独立验证 Agent 实际编译/测试核验 → 未过自动回炉修复，全程用 token 换质量。查询类请求不走深度链（2026.10.02 起）：问句/合查询动词（是什么、为什么、帮我看看、分析…）且不含改码动词的提示词直接回答（日志提示「ℹ 查询类请求，跳过专家模式深度链」）——规划与验证是改码质量保障，对查询纯属干扰。深度链过程输出已压缩上屏：规划/验证轮的长文本只保首段，结论以事件判定行为准（✔ 独立验证通过 / ⚠ 验证未通过回炉），不再刷屏淹没执行结果。

助手运行中发送的提示词去哪了？

助手运行中再发送的指令不会立刻打进日志，而是暂存在日志区右下角的小折叠框里（默认只显示第一条，点左侧小箭头展开全部）。未发送的排队指令可以编辑或删除：展开后每条右侧有 ✕ 按钮，或右键该条选「编辑…/删除」（折叠状态下右键首条也能操作）——删除的指令不会再发送，编辑后的文本以修改后内容投送。指令实际开始处理时才正式进入日志（轮中注入的后端立即生效；排队类后端在本轮结束后自动续发——若积了多条会自动合并成一轮一次性投送，不会一条一轮地串行跑）。若提示「请稍候」（助手处于崩溃宽限/重试窗口），指令会自动退回输入框。用户提示词上方有一条 3px 分隔线，便于区分每一轮提问。

提示「达到轮次上限，自动续跑」是什么意思？

这不是错误，是护栏机制：助手单条提示词一次执行最多跑 40 轮（每轮＝模型思考＋工具调用，读文件/改代码/构建都算），达到上限时 AutoCode 会自动续跑（最多 2 次）接着干，已完成的工作全部落盘不丢；若三次共 120 轮仍未干完，会保留断点并提示发送「继续」接着做。频繁触顶说明单条提示词任务太大（如多文件重构＋自测＋构建），两个办法：① 拆任务——把大需求拆成多条小提示词分步发送（推荐，每步都可验证）；② 调上限——设置 → 运行策略 → 「助手轮次上限」（10～200，[Adhoc] MaxTurns，默认 40），保存后下一条提示词即生效。此外 AutoCode 会在发送前自动做工作量评估（2026.09.23 新增，纯本地启发式、零 token）：按提示词里的编号子任务数、点名的源文件数、重活关键词（重构/自测/构建…）与文本长度综合估算，重任务自动上调本轮轮次预算（日志提示「⚙ 工作量评估：轮次上限 40 → N」），小任务不受影响、只升不降；勾选框「按提示词工作量自动上调」可关闭（[Adhoc] MaxTurnsAuto，默认开）。

「日志渲染引擎」新旧版有什么区别？切换会丢会话记录吗？

这是任务/助手日志区的渲染方式灰度开关（设置 → 常用 → 评审与助手）：「旧版（卡片流）」每条消息一个控件块，长期默认、短会话最稳妥；「新版（自绘）」（2026-10-17）改用 Model/View 虚拟化——只绘制可视区、滚动全程零消息子控件、正文排版按视口带惰性材化，长会话（数千条消息）载档、滚动与跳转明显更流畅，交互完全等价（折叠/展开、双击助手消息拖选复制、链接单击打开、错误工具卡标红——实时回填的单条卡自动展开）。两档随时互切、会话记录零迁移零丢失：会话正本始终存于任务/助手目录的 chat.json / assistant.json，渲染引擎只决定显示方式，切回旧版一切照旧。切换保存后对新建立的会话页生效（状态栏有提示），重开助手 Tab 或重启程序后全部生效。
